TARGET / CLAIM CARD
-------------------
Target:
  quantify the STORE-versus-RECOMP tradeoff for the full Q4 edge-cover predicate.

Input family:
  32 clause-presence bits of full genuine four-variable 3-SAT.

Equivalent function:
  UNSAT iff the selected Q4 edges cover all 16 vertices.

Machine/model:
  deterministic branching programs.
  The fixed endpoint-scan architecture processes Q4 vertices 0,...,15.
  A designated set K of edge variables may be forgotten and queried again at the second endpoint.
  Variables outside K retain their first queried value until the second endpoint and are never reread.

Resource:
  nonterminal query-node count, plus repeated-variable count and total query count.

Quantifiers:
  Construction upper bounds: there exists an explicit BP with the reported resource.
  No global minimum over all BPs is claimed.

Known barriers:
  restricted BP size != arbitrary SAT runtime;
  read-k lower-bound methods weaken sharply as rereading is allowed;
  n=4 occurrence two is exceptional.

LITERATURE
----------
1. Woelfel's Definition 2 distinguishes semantic read-k and (1,+k) restrictions:
   a (1,+k)-BP has at most k variables appearing more than once on each computation path.
   The paper proves lower bounds for k-wise l-mixed functions, but the condition kl<=n makes
   this technique intrinsically weak in the present 32-bit laboratory once k is around n/2.
2. Jukna-Razborov prove lower bounds 2^{Omega(min{d1,d2/s})} for (1,+s)-BPs computing
   suitable linear-code characteristic functions and obtain superpolynomial bounds for
   s=o(n/log n). Their hypotheses do not apply directly to Q4 edge cover.
3. Savicky-Zak establish strict hierarchies in the (1,+k) model; even (1,+1) can be
   strictly more powerful than read-once.
4. Razgon 2025 makes the "splitting power" of bounded repetition explicit for bounded-width,
   bounded-occurrence CNFs and gives a read-twice upper bound through a conjunction of two OBDDs.
5. Li-McKenzie 2024 emphasize that even read-once BP lower-bound measures do not naturally
   extend to all read-k computations.

NEW RESULT A: 64 NODES WITH AT MOST 14 REREAD VARIABLES ON CONSISTENT PATHS
---------------------------------------------------------------------------
Start from the 64-node vertex-by-vertex star-scan BP:
  for each Q4 vertex, query its four incident edge variables until one is 1;
  reject if all four are 0; accept after all vertices succeed.

Every input variable occurs in exactly two query nodes globally, one per endpoint, so the
program is syntactic read-twice.

A seeded local search over the four-edge order at each vertex found the following fixed
dimension orders:
  [1,3,0,2], [2,0,3,1], [2,0,3,1], [1,3,0,2],
  [2,3,1,0], [0,3,1,2], [0,1,3,2], [2,1,3,0],
  [2,0,3,1], [1,3,0,2], [1,3,0,2], [2,0,3,1],
  [0,1,3,2], [2,1,3,0], [2,3,1,0], [0,3,1,2].

Exact dynamic analysis of all consistent computation paths gives:
  maximum total queries over the full 32-bit domain = 43;
  maximum number of distinct variables queried twice on one consistent path = 14.

Therefore this explicit 64-node program is:
  - syntactic read-twice;
  - a semantic (1,+14)-BP.

Perfect-matching hostile subfamily:
  272 perfect matchings;
  every perfect matching uses exactly 40 total queries;
  repeated-variable count min/average/max = 8 / 10.117647... / 13.

Architecture-specific lower bound:
On any perfect-matching input, the eight selected matching edges are the unique selected
incident edge at their endpoints, so every one of those eight variables is necessarily
queried at both endpoints in ANY vertex-by-vertex star-scan program.
Hence every such architecture repeats at least 8 variables on every perfect matching.
Thus, for this architecture only:
  8 <= optimal semantic reread budget <= 14.

Independent exact-weight-8 verifier for the above order:
  C(32,8)=10,518,300 inputs;
  edge covers/perfect matchings = 272;
  mismatches = 0;
  worst weight-8 total queries = 42.
Correctness on the total function follows symbolically from checking every vertex-cover clause.

NEW RESULT B: IMPROVED STORE/RECOMP CURVE
------------------------------------------
Fixed architecture:
- vertex order 0,...,15;
- incident edges scanned in ascending edge-id order;
- if e notin K, its first queried value is retained until the later endpoint;
- if e in K, its value is discarded and a second endpoint query is allowed;
- identical query subgraphs are hash-consed exactly;
- redundant query nodes with identical 0/1 successors are removed.

Only variables in K can be reread, and each can be read at most twice. Thus every constructed
program is a syntactic (1,+|K|) read-twice BP.

Greedy valid upper-bound curve:
  k=0   : 1592 nodes
  k=1   : 1193
  k=2   : 945
  k=4   : 610
  k=8   : 298
  k=12  : 168
  k=16  : 114
  k=20  : 88
  k=24  : 70
  k=28  : 65 on the greedy chain
  k=29  : 64
  k=30  : 62
  k=31  : 63 for that exact greedy set, but <=62 when the k=30 construction is allowed
  k=32  : 64 for full forgetting, but <=62 when the k=30 construction is allowed.

This improves the previous READ-REPETITION-Q4-7 upper-bound curve at every reported low-k point
and answers one of READ-TWICE-Q4-6's open questions:
  a hybrid STORE/RECOMP BP with fewer than 64 nodes DOES exist.
Current explicit global read-twice upper bound:
  size <= 62.

EXHAUSTIVE HIGH-k TAIL INSIDE THIS FIXED ARCHITECTURE
------------------------------------------------------
Exhausting every choice of stored variables gives exact minima for exact forget-set sizes:
  k=28 (store 4): 64 nodes, store edges {0,7,12,31}
  k=29 (store 3): 63 nodes, store edges {0,7,31}
  k=30 (store 2): 62 nodes, store edges {0,31}
  k=31 (store 1): 63 nodes, store edge {0}
  k=32 (store 0): 64 nodes.

These are exact minima ONLY inside the declared fixed vertex/local-order endpoint-scan architecture.
The nonmonotone exact-k tail is natural: forcing too much forgetting can destroy sharing. In the
usual "at most k reread-enabled variables" interpretation the upper-bound curve is monotone, so
the 62-node k=30 construction remains available for k=31,32.

MODEL INTERPRETATION
--------------------
The finite experiment gives a clean STORE/FORGET/RECOMPUTE phenomenon:
  read once and remember frontier values -> larger DAG;
  forget selected values and legally reread -> much smaller DAG.

This directly matches the role of bounded repetition in the classical (1,+k) literature and
Razgon's modern "splitting power" viewpoint.

The result also separates resources:
- Rivest-Vuillemin evasiveness still forces 32 DISTINCT input bits to be inspected on some input
  for the total Q4 edge-cover function;
- the 64-node star program can spend up to 43 TOTAL queries because of rereads;
- DAG node count can fall to 62 through STORE/RECOMP;
- these are different resources and should not be conflated.

ASYMPTOTIC HOSTILE CONTROL
--------------------------
The Q4 collapse is special.
For n-variable genuine 3-SAT:
- there are 2^n assignments;
- each assignment is falsified by C(n,3) genuine signed 3-clauses;
- each clause is falsified by 2^(n-3) assignments.

The direct assignment-cover branching program therefore has:
  2^n * C(n,3) query nodes
and is syntactic read-2^(n-3), not constant-read.

For n=5 this already becomes a 320-node read-4 construction.
Thus the finite Q4 read-twice collapse does not yield an asymptotic SAT algorithm.
