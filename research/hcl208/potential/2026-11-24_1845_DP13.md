## A. Probe-stable rank certificate (PROVED)
Assume DP12's independent private/edge coordinate adapter, now on an arbitrary finite loopless regional graph (parallel edges allowed). Source-equivalent Boolean factors are authenticated explicitly, and each has a signed affine list whose coupling expansion is capped by N^a for a fixed a. Expand each packet using DP12 character orthogonality into L_i polynomially many labels. Private factors are absorbed into local signed coefficient a_i(t). Each edge e=ij has endpoint functions h_it(y), h_js(y) on its actual independent F2 edge block. The label partition sum is
 Z = sum_(t_1,...,t_m) product_i a_i(t_i) product_e K_e(t_i,t_j),
 K_e(t,s)=sum_y h_it(y)h_js(y)w_e(y).
Here w_e is 1, a coordinate-prefix pin indicator, a single parity character, or the product of the latter two. Private blocks and unused coordinates receive the same query weight once, never at both endpoints. Global parity indicators are reconstructed as (Z+/-E)/2. This retains all original correlations; arbitrary external guards are not free. The normalization of DP12 coefficients is kept exact.

For each incidence compute its unweighted self-Gram G_i(t,t')=sum_y h_it(y)h_it'(y) using DP12 Gaussian affine-character intersection sums. Over Q, rank(G_i) equals dimension of the span of the actual functions (positive real inner product). Let r_e=min(rank G_i,rank G_j). A zero endpoint span certifies zero count. Choose the smaller endpoint, say i, choose basis functions B_1,...,B_r from a nonsingular principal Gram submatrix, and solve exactly for coefficients U(t,k) in h_it=sum_k U(t,k)B_k; the equality holds as functions, not just on one query. Cramer's rule or exact Gaussian elimination yields rational coefficients of polynomial bit length, since determinants of polynomial matrices with polynomial-bit entries have polynomial bit length. Then for ALL allowed weights,
 K_e(t,s)=sum_k U(t,k) V_w(s,k), V_w(s,k)=sum_y B_k(y)h_js(y)w_e(y).
Each entry is a polynomial Gaussian job. A rank-one edge is a product of unary factors, removable from the graph after multiplying its two factors into the endpoint coefficient vectors. This includes signed and zero query factors. A zero product entry is not a witness. Rank-one removal is valid for all probes without recharting. Unlike rank of the unweighted cross-Gram, r_e is probe-stable. Explicit counterexample on two bits x,y: endpoint families (1,(-1)^y) and (1,(-1)^(x+y)). Unweighted K=diag(4,0), rank1; pin x=0 gives diag(2,2), rank2. Both endpoint ranks are 2. Thus using only the actual unweighted cross-rank as a reusable closure reserve is FALSIFIED.

## B. Block-local feedback contraction (PROVED)
After removing all robust rank-one edges, discover vertex-biconnected edge blocks (bridges count as singleton blocks) and the block-cut forest by DFS. Parallel edges are distinguished by ID. For block B, choose a spanning tree T_B. For each non-tree edge replace its K by the exact r_e-term decomposition above, and sum over one auxiliary index k_e per cut edge. Each fixed index tuple multiplies unary factors into the incident vertex coefficients; the remaining tree is evaluated by ordinary DP12 label messages. Put
 R_B=product_(e in B minus T_B) r_e.
A maximum spanning tree under weights log r_e minimizes R_B among all spanning trees of B: product of all ranks is fixed and maximizing sum of log ranks on T_B is equivalent to maximizing their product. Kruskal needs only integer rank order; no floating-point logs. This optimizes this specific slicing strategy, not arbitrary contraction complexity.

Root the block-cut forest at vertices. Each articulation v multiplies its own original coefficient (including absorbed rank-one factors) by the child-block message vectors indexed by the SAME v label. A block message to its parent articulation is computed as a vector over all parent labels; exclude the parent's original coefficient and its other incident blocks. Other vertices incorporate their child-block vectors once before slicing. Sum all R_B slice vectors to produce the parent message. Inductively each message is the exact partial partition sum conditioned on that one label, since distinct child blocks meet only at the articulation and every edge is assigned once. Roots sum their weighted labels, disconnected components multiply. This proves exact signed cancellation, no duplicate vertex coefficient, no independent treatment of correlated labels, no full global tuple materialization. The signed labels and auxiliary indices need not correspond to actual assignments; only the authenticated final nonnegative Boolean count gives a SAT decision.

Define l_i=max(1,L_i), and
 J = 1 + sum_i (1+deg(i)) l_i + sum_(e=ij) l_i l_j
       + sum_B R_B [1+sum_(i in B)(1+deg_B(i)) l_i
                        +sum_(e=ij in T_B) l_i l_j].
The first terms cover acquisition/matrix and unary/consumer jobs up to polynomial arithmetic factors; the last covers all tuple enumeration, tree messages and block aggregation (counting every repeated slice and parent-label vector entry). A bound on R_B alone is not enough if label growth or acquisition is uncharged. J is computable using polynomial-bit products without actually enumerating tuples; decline before expensive execution if J>N^b for fixed b. For a fixed query set Q (or fixed polynomial maximum query allowance), reserve |Q| J plus preprocessing, verification, output and closure budgets. Split each block into its locally paid slice jobs after child messages are available, and charge each child block once, not once per parent slice. A schedule can allocate disjoint future jobs to child tasks, including local setup and parent aggregation, yielding sum child mu <= mu(parent)-1 with c=1, where mu is the remaining integer job reserve. Cached child vectors are shared but all reads are paid; retained state IDs include source, query weights, label basis and block. This is a paid terminal/schedule potential, not an arbitrary semantic residual potential or a universal OR-branching theorem. Independent components/blocks add work, not multiply their feedback products. Query-specific rank factorizations can improve one count but cannot be reused without proof.
