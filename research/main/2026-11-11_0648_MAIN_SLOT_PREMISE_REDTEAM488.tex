\section*{2. Theorem 488.1 (PROVED/RESTRICTED): accepted length is unbounded at fixed record count}
Let $D$ be the /540 seed packet and, for $m\ge0$, let $Q_m$ be $\mathtt{JSON.stringify}$ of $D$ with one additional top-level key \texttt{"pad"} whose value is $m$ ASCII letters \texttt{a} (and $S_m$ the same with the key on record 0). Within representable JavaScript limits, the unchanged checker accepts $Q_m$ and $S_m$ with
\[
W=31,\qquad N_{\mathrm{records}}=49,\qquad L(Q_m)=L(S_m)=3088+m .
\]
\emph{Proof.} \texttt{checkProof} reads only \texttt{spec}, \texttt{records}, \texttt{gate\_defs}, \texttt{summary} and, per record, \texttt{kind}, \texttt{c}, \texttt{parents}, \texttt{pivot}, \texttt{source}, \texttt{gate}; no check enumerates keys, so an extra key alters no tested value. Each of the eleven CLI mutators modifies a read field and still produces the same rejection as on $D$ (structuredClone copies the pad unchanged). The output is canonical (no whitespace), so this is distinct from the LSPV-4/413 whitespace lemma. $\square$

\textbf{Corollary 488.2.} For the original program the 543 bound $2N$ satisfies, over accepted packets,
\[
\min_{P\ \mathrm{accepted},\,|P|=L}2N(P)\le 98\quad\text{for every }L\ge3088,
\qquad
\max_{P\ \mathrm{accepted},\,|P|\le L}2N(P)=\Theta(L)
\]
(the upper envelope by the 543 family $P_k$, using $N\le L$). Hence the statement ``the /386 checker forces slots linear in packet size'' holds only for the explicit family $P_k$ (as 543 itself states) and is \textbf{FALSIFIED} as a universal statement over accepted inputs. Conversely, the CLI's $11$ structuredClone calls copy the pad, so its sequential copy work is $\ge 11m$ on $Q_m$: work and slot count decouple in opposite directions.

\section*{4. Literature and barrier transfer}
