\section{Primary source and exact machine issue}
Fortnow--Lipton--van Melkebeek--Viglas (FLMV) use random-access Turing
machines with read-only input, write-only one-way output, and counted work and
index tapes.  An indexed move erases the relevant index tape.  In their
Theorem~3.4 proof, the simulated SAT input is never materialized; every
addressed Cook-formula bit is recomputed from the original source in
polylogarithmic time and logarithmic workspace.  This is a genuine primary
source for virtual input, but its reduction supplies a complete formula
encoding, not merely a partial valid-address function.

LSPV-4 ARC-MATERIALIZE-GUARD253 already proves that blindly redirecting a
guest's far read-only-input jump to a materialized work-tape child can consume
the far indexed position as charged workspace.  It correctly requires
comparing the guest address with the exact child length and returning blank for
an out-of-range jump.  The report explicitly leaves subsequent ordinary
input-head moves and a complete simulator open.  The theorem below attacks
that precise remainder.

Seiferas--Vit\'anyi prove that a fixed number of increment/decrement/sign
counters can be simulated in real time on a one-tape Turing machine with
logarithmic space.  This is relevant to tracking distance from the child
boundary.  It is not imported as a completed theorem transfer: the present
ARC use additionally needs loading an arbitrary binary address before the
model erases the guest index tape, exact child-boundary tests, source-bit
access, and an all-tape simultaneous ledger in the FLMV model.

\section{A sticky-guard counterexample}
Number the nonempty child input cells $0,\ldots,m-1$; every other cell is
blank.  A \emph{sticky-OOB simulator} handles a guest indexed jump to
$j\ge m$ by entering a special OOB state, returns blank there, and continues
returning blank after ordinary left/right guest input-head moves until the next
indexed guest jump.  On valid indexed jumps it returns the exact child bit.

\begin{theorem}[Far-jump guarding alone does not simulate ordinary re-entry]
Let $B$ be any total exact ordinary-SAT decider.  There is a fixed total exact
ordinary-SAT decider $A_B$ with only $O(m)$ additional time and
$O(\log m)$ additional writable space on an $m$-bit input such that every
sticky-OOB simulation of $A_B$ is wrong on every valid nonempty SAT encoding
whose last bit is $1$.  The error occurs on SAT and UNSAT inputs alike.
\end{theorem}
\begin{proof}
On its ordinary physical input, $A_B$ first scans to determine $m$.  It then
indexes its read-only input head to cell $m+1$, observes blank, moves the input
head left twice, and records the symbol $r$ now read at cell $m-1$.  Next it
performs a valid indexed jump to $m-1$ and records the symbol $s$.  Finally it
runs $B$ and returns $B$'s answer if $r=s$, and the complementary bit otherwise.

On every ordinary physical nonempty input, both reads are of the same cell
$m-1$, so $r=s$ and $A_B$ returns exactly $B$'s answer.  The wrapper is
therefore correct on both labels; it receives no answer bit.  Its scan, two
indexed jumps, two ordinary moves and two stored symbols have the stated
overhead.

In the sticky-OOB simulation, the jump to $m+1$ enters OOB.  The two ordinary
left moves are lost by definition, so the first recorded symbol is blank.
The later valid indexed jump to $m-1$ exits OOB and returns the actual last
bit, which is $1$.  Thus $r\ne s$ and the simulated wrapper complements the
correct answer.  The argument is independent of whether the source is SAT or
UNSAT.  \qedhere
\end{proof}

\begin{lemma}[Valid-domain-only access is also insufficient]
For a logical child $y$ of length $m$, correctness of
$g(F,j)=y_j$ only for $0\le j<m$ does not imply correct simulation of an
arbitrary ordinary-input guest.
\end{lemma}
\begin{proof}
Use the same wrapper idea but probe cell $m$ and complement $B$ if the returned
symbol is nonblank.  A physical input returns blank.  Any extension of $g$
outside its promise may return a source bit and reverse the answer.  Therefore
either a total accessor with ordinary blank semantics or an independently
proved complete head simulator is load-bearing.
\end{proof}

The theorem is deliberately narrow.  It is not a lower bound against every
possible simulator.  A correct simulator may retain an exact or compressed
logical head coordinate and update it under ordinary moves.  The result proves
only that the previously suggested one-time guard is necessary but not
sufficient.

\section{Conditional exponent ledger after the correction}
Suppose, beyond what is proved here, that a controller discovers at most
$N^{\gamma+o(1)}$ serial ordinary children of length
$m\le N^{\lambda+o(1)}$, spends $N^{\alpha+o(1)}$ non-guest time and
$N^{\sigma+o(1)}$ retained workspace, and has a \emph{complete} total child
access/head simulator costing $N^{\delta+o(1)}$ per guest step and
$N^{\eta+o(1)}$ reusable scratch.  For one fixed guest with simultaneous
exponents $(K,L)$, the valid conditional envelope is
\[
 K'\le\max\{\alpha,\gamma+\delta+\lambda K\},\qquad
 L'\le\max\{\sigma,\eta,\lambda L\}.
\]
The input-length test, indexed-address capture, ordinary head updates,
blank semantics, guest work/index tapes, failed policies, conversion,
replay and ancestor state must all lie inside these displayed terms.  A
valid-address emitter alone does not establish either inequality.

For the current nominal $(\alpha,\gamma,\lambda,\sigma)=(11/10,3/5,1/2,1/2)$,
LSPV-4's exact joint-slope referee gives
\[
 K_* = \max\{1.1+\pi,1.2+2\delta\},\qquad L_*=1/2+\eta
\]
under its declared tariff convention.  Strict entry at the $c=241/200$
FLMV slice requires strict positive margins, including
$\delta<1/400$ when $\pi=\eta=0$.  The present theorem neither attains nor
rules out those margins; it prevents an incomplete sticky guard from being
priced at zero.

Finite iteration does not itself create nonuniform advice: for a fixed guest
$A$ and fixed iteration count $r$, the compiled program may have constants
depending on $A,r$ but not on the input.  However, the previous LSPV-5
exponent-discovery firewall forbids granting the controller a computable
oracle for the guest's tight exponent.  A hereditary recurrence must therefore
be exponent-oblivious or use an explicit separately verified syntactic
certificate; the guest-head repair cannot choose its implementation from a
free unknown-$K$ bit.
