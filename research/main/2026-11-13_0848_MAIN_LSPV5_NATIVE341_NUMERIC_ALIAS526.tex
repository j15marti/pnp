\section{Target claim and falsifiers}
\textbf{Target.} The historical \texttt{/341} checker accepts JSON numeric lexical aliases
whenever \texttt{JSON.parse} maps them to the same JavaScript Number as a canonical integer.
This falsifies any claim that the accepted-byte grammar requires one canonical decimal integer
spelling at graph, source, proof-support, or truth-table coordinates.

Falsifiers were: (1) a pre-parse canonical-number lexer rejects an alias; (2) the checker retains
and compares numeric lexemes; (3) an alias changes the parsed proof, result, or logical work; or
(4) nonintegral controls are also accepted, showing only an untyped numeric hole rather than a
lexical quotient.

Every mutation and their composite packet was accepted with exactly the baseline parsed output,
30,714 checks, and seven family results. The composite SHA-256 is
\texttt{f888dfd76f47016132f852d5ea52f74828f4e55a34d25a3402bdc9b88d3f40db}.
Three nonintegral controls were rejected: vertex \texttt{0.5}, literal \texttt{1.5}, and table
\texttt{246.5}.

Let $P$ be \texttt{JSON.parse} and $V$ the verifier. The archived program computes $V(P(b))$ and
never receives numeric token spellings. Consequently $P(b)=P(b')$ implies equal verification
behavior. The concrete replays establish this equality for all eight aliases and the composite.
Thus the historical accepted-byte language is not a canonical-decimal-integer language at the
tested coordinates, although its parsed values remain integral.

\section{Concrete semantics, abstraction, cost, and CEGAR}
A faithful concrete semantics must include raw bytes and the parse transition. A parsed-Number
abstraction soundly quotients these aliases only if it does not later claim canonical byte
authentication. All cheap alias paths were concretely replayed; they are genuine and may not be
removed by refinement. A field-specific canonical integer lexer is a repaired, versioned grammar,
not the historical calculus. Logical work is unchanged, while physical byte length and parsing
cost differ and must be charged in any machine-resource model.

\section{DUPLICATION / CONTRADICTION AUDIT}
Run 525 established duplicate-member last-wins behavior. Run 526 is distinct: every packet has
unique member names and attacks numeric token spellings. It narrows, rather than contradicts, the
typed parsed-object results: integral semantic values are checked, canonical numeric bytes are not.

\section{WHAT CHANGED RELATIVE TO ROOT MAIN}
The /341 raw-byte front end is now known to quotient both duplicate members and integral numeric
lexical aliases. The parsed-object theorem remains unchanged at its exact scope.

\section{ADOPTED / REJECTED / RETIRED PRIOR COMPONENTS}
Adopted the archived source, full fixture, and source-first raw-byte semantics. Rejected silently
substituting a canonical-number grammar for the historical parser. Retired no logical theorem.

\section{STALE OR OVERSTATED CLAIMS FOUND}
Any claim that /341 accepts only ordinary base-ten integer tokens is overstated. It accepts the
tested JSON exponent, decimal, and negative-zero aliases whenever their parsed Number is integral.
