\section{Exact obstruction and four falsifiers}
REFEREE265 established exact aligned residual-function equality as a sufficient semantic answer quotient.  The new obstruction is whether that equality also transports a cached \emph{proof object}, its assumption environment, or its execution cost.

This run tested four falsifiers.
\begin{enumerate}
\item \emph{Equal residual functions make raw UNSAT certificates interchangeable.}  Two authenticated Y6 affine leaves both represent the identically false function, but all four minimal row-XOR certificates fail cross-node provenance checking.
\item \emph{Checking that proof rows XOR to $0=1$ is enough.}  Every cross-node triple still arithmetically XORs to $0=1$, but contains rows absent from the target node.  Omitting source-row/assumption authentication would accept an ill-typed proof.

\item \emph{The typed cache closes ARC/FLMV.}  F9 remains easy for reference UP-DPLL despite three exhausted affine branches; children are noncanonical; and no all-input equality oracle, hereditary re-encoder or numerical SAT-to-target transfer is supplied.
\end{enumerate}

\section{Typed certificate-transport theorem}
Let $s$ be a certificate-DAG node, $f_s$ its exact aligned residual source function, $E_s$ its authenticated row/assumption/provenance environment, and $V(E_s,C)$ a sound proof checker.  A weighted residual function additionally records source projection and multiplicity.

\begin{theorem}[Answer equality versus proof transport]
If $f_s=f_t$, the semantic SAT/UNSAT answer may be shared.  A raw proof object $C$ may be reused at $t$ only if
\[
  V(E_t,C)=\mathsf{accept},
\]
or a checked translator $\tau_{s\to t}$ produces $C'$ with $V(E_t,C')=\mathsf{accept}$.  Equality $f_s=f_t$ alone does not imply either condition.  Exact \#SAT sharing additionally requires equality of weighted residual functions.  None of these semantic equalities bounds the cost of recognizing equality, translating/checking certificates, executing a guest, or retaining simultaneous state.
\end{theorem}
\begin{proof}
Pointwise equality gives identical emptiness, hence the same scalar decision.  Sound acceptance by the target verifier proves the target claim; a checked translator reduces to that case.  But proof syntax derives consequences from a declared environment.  Two environments may define the same function while containing different authenticated premises, so a derivation valid in one need not be a derivation in the other.  Counts can differ under unequal projection multiplicities even when Boolean support agrees.  Finally, inserting any number of read-only DELAY steps leaves the function unchanged and changes time, so semantic equality alone cannot determine resource cost.
\end{proof}

\begin{corollary}[Cache record type]
A replayable cache entry needs at least the semantic answer plus a target-checkable certificate and its assumption/provenance domain (or a checked translation).  For counting it also needs the output projection/multiplicity contract.  Storing only a semantic node identifier is sound for the scalar answer, not automatically for proof replay or resource accounting.
\end{corollary}

This sharpens REFEREE264's completion-domain rule and REFEREE265's semantic quotient.  It is consistent with incremental SAT proof formats that explicitly delimit queries and assumptions, and with LRAT-style checkers that validate dependency hints against a trusted clause environment.

\section{Explicit authenticated Y6 falsifier}
Use the valid duplicate-free proper monotone 3-SAT-$(2,2)$ source
\[
123,145,246,356,\overline{124},\overline{136},\overline{235},\overline{456}

under $x_5=0,x_6=1$.  Its cost-one affine partition has eight profiles.  Profiles 1 and 5 are both inconsistent on all sixteen aligned free assignments, so their exact residual masks are both zero and their exact model families are both empty.

Write $D_j$ for the authenticated default parity row of original source clause $j$, and $U_{j}:x=b$ for an exact selected-ticket unit row.  Exhaustive subset search finds exactly two minimum three-row contradictions per leaf:
\[
\begin{array}{c|l}
\text{profile 1}&D_1\oplus D_4\oplus(U_0:x_2=0)=0=1\\
&D_5\oplus(U_0:x_1=1)\oplus(U_0:x_3=1)=0=1\\[2pt]
\text{profile 5}&D_0\oplus D_5\oplus(U_4:x_2=1)=0=1\\
&D_1\oplus(U_4:x_1=0)\oplus(U_4:x_4=0)=0=1.
\end{array}
\]
All four certificates pass in their native environment.  Both profile-1 certificates fail at profile 5 because two source-tagged rows are missing; both profile-5 certificates fail at profile 1 for the same reason.  Importantly, every rejected certificate still XORs arithmetically to $0=1$.  The failure is provenance/assumption typing, not GF$(2)$ arithmetic.

The same source supplies both labels independently: the parent cube has six models; adding $x_3=1,x_4=0$ leaves zero.  Original Y6 has twenty models although $0^6$ and $1^6$ both fail.
