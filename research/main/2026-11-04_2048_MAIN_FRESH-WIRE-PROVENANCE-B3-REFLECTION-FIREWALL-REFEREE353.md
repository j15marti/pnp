## ITERATE I: completion-independent fresh semantic-variable provenance

### Typed definition

A **public semantic variable** is a Boolean assignment coordinate appearing in a source/derived clause, factor support, GF(2) mask, DEF input/output, or other downstream semantic condition. A LOCAL-payload gate label used only to serialize an expression inside that one conclusion is not, merely by being a syntax label, a public semantic variable. The unresolved question whether a subexpression/row may be selected by a path is explicitly outside this theorem.

### Theorem (native paid fresh-wire provenance)

In every legal original-`R_mix341` proof, each public semantic variable not declared by the source DIMACS header has one unique earlier paid DEF owner. Consequently, if `k` distinct non-source public semantic variables occur, the proof contains at least `k` paid DEF nodes and hence has paid cost at least `k`.

**Proof.** Induct over the topological proof order. Initially the only semantic variables are source variables `1,...,n`. RES derives a clause over variables already occurring in its parent clauses. AND3 derives the exact conjunction of two existing conditions. XOR sums two existing masks. LOCAL derives one consequence of an already derived factor/equation. None of those rule signatures licenses introduction of a fresh semantic variable. DEF alone explicitly introduces **one fresh variable**, requires its inputs to be previous wires, and is conservative with unique extension. Freshness makes the owner unique, and its node has unit cost. Induction gives the provenance statement; counting owners gives `k <= #DEF <= q`. QED.

**Exact consequence.** A validator that turns a LOCAL-internal gate name into a new public clause/GF(2)/factor variable without a paid DEF accepts a non-native rule. A legal paid DEF may expose one fresh semantic output. This does **not** decide whether the paid DEF node's XOR relation is addressable as a GF(2) equation, whether an old defining-clause facet is selectable, or whether a path to an expression over already-owned variables is a legal port. LSPV-2/407 proves that those selector bytes remain underdetermined.

## ITERATE II: minimal legal native counterexample to consumer-blind normalization

Let the original SAT source be

`F = (x) AND (NOT y)`.

It has exactly one model, `x=1,y=0`. The following is legal under the unambiguous native fragment and has three paid nodes:

1. AND3 on the two source clauses yields the exact factor `x AND NOT y`, with truth table `[0,0,1,0]` in order `00,01,10,11`.
2. LOCAL-CONVERT derives `(x OR y)`, entailed by that factor.
3. RES on pivot `y` between `(x OR y)` and the original source `(NOT y)` derives `(x)`.

Now independently replace only node 2 by the stronger, still entailed `(x)` and retain node 3. The named pivot `y` is absent, so node 3 is no longer a legal RES inference. This is a **fully legal original-rule input fragment** refuting edge-preserving, consumer-blind per-node root normalization. It is not a counterexample to a global consumer-aware compiler.

Three derived nodes are minimal for this obstruction form: native LOCAL requires one already derived factor/equation parent; the changed LOCAL conclusion is the second node; exhibiting a broken downstream consumer requires a third. The source improves LSPV-4/400's three-variable/three-clause fixture to two variables/two clauses while reproducing the same obstruction independently.

## ITERATE III: noncircular B3 audit

The target remains

`SAT in P  =>  exists C,k forall N: Wbar_Rmix341(N) <= C(N+1)^k`.

No proof or refutation of this **same-fixed-system** implication was obtained. Three tempting bridge schemata are nevertheless refuted exactly:

1. **Rejecting-trace bridge fails by type.** An arbitrary SAT decider's configurations are not clauses, support-three factors, GF(2) equations, LOCAL consequences or conservative DEF gates. Declaring a rejecting trace to be an R line adds a machine-correctness/reflection rule absent from `/341`. Proving each trace's global correctness inside R is precisely the missing reflection/source-retraction theorem.
2. **Polynomial prefix-search bridge is circular for B3.** Suppose a global polynomial `L(N)` already bounds encoded accepted `R_mix341` certificates for all UNSAT sources. Since every paid node has a nonempty encoding and unit weight, `W_R(F) <= number_of_nodes <= encoded_bits <= L(N)`. Thus the premise already implies B3 before prefix search begins. SAT in P can help *find* a promised short proof, but cannot prove the promise.
3. **Cook--Reckhow existence changes systems.** SAT in P implies NP=coNP and therefore existence of some polynomially bounded proof system. Cook--Reckhow Proposition 1.6 transfers that bound to the preselected `R_mix341` only if `R_mix341` polynomially simulates that system. No such compiler has been proved. Treating it as automatic reverses the required simulation or silently replaces R.

REFEREE352's fixed `R_lock2`/2-SAT construction already disproves any generic claim that soundness, completeness, fixedness, positive weights, bounded premises and polynomial checking alone force B3. The same source has native `R_mix341` cost one, so that control does not refute actual B3. The present provenance theorem also does not: it supplies a necessary paid-name invariant, not polynomial proof existence.

## Established hard-family controls

- **Haken PHP:** for the standard unary CNF encoding of `PHP_(h+1)^h`, with `h(h+1)` variables and `Theta(h^3)` clauses (`Theta(h^3 log h)` signed-index bits), every ordinary shared-DAG Resolution refutation has `2^{Omega(h)}` size. The quantification is over Resolution refutations only. DEF, LOCAL, GF(2), ER and arbitrary algorithms are outside the theorem.
- **Cook ER:** extension variables give polynomial PHP proofs; therefore the Haken lower bound cannot be transferred through paid DEF without a proved backtranslation.
- **Odd Tseitin:** the original `/341` family has exact linear `R_mix341` proofs by AND3/GF(2), so Resolution hardness is defeated inside the fixed mixed system.
- **Braun bit-PHP Res(`oplus`):** the recent unrestricted-DAG lower bound concerns disjunctions of affine equations and a bit-PHP encoding. It is not a lower bound for `R_mix341`, ER or SAT machines. Any translation must be polynomial in the correct direction and preserve the legal public-port grammar.

## Physical-cost ledger

Let `N` be source bits, `E` supplied proof-record bits, `q` paid nodes and `D` paid DEF outputs. The theorem is about logical node cost. It does not make any of the following free:

- reading and validating all `E` bytes/bits, source indices, signs, node IDs and variable IDs;
- checking freshness, uniqueness, topological order and every consumer;
- constructing a canonical renaming or rewriting all references;
- serializing the output, verifying it, retaining lookup state or recomputing it;
- peak memory, index/head state, caches, guest machines or failed attempts.

A buffered dictionary implementation can scan in polynomial time with `O(E)`-scale host storage. A read-only-input repeated-scan implementation can compare variable fields and discover owners with conservative polynomial bit time (for example `O(E^3)` under naive substring rescans) and `O(log E)` counters, plus output; this is not an FLMV-native measured bound. The Python host RSS was not measured. Every differing physical bit and every read/write/move still costs machine work. An `E`-bit opaque LOCAL payload remains an `E`-bit physical object even when it is one logical node.

The fresh-name theorem gives `D <= q` and permits canonical names of `O(log(N+q))` bits for DEF outputs, consistent with LSPV-4/402. It does not bound a LOCAL private circuit payload or the number/size of selectable facets. Hence it does not close polynomial certificate-bit balance and cannot activate LSPV-1/408 noncircularly.

## Precise outcome and next unresolved step

**Settled:** free export of a new *semantic variable* is illegal; one fresh semantic output requires one unique paid DEF owner. Consumer-blind root normalization is false already on a minimal three-node legal native fragment.

**Not settled:** whether paid DEF defining rows/clauses and LOCAL subexpressions have addressable port selectors. The LSPV-2/407 discriminator proves the prose does not choose a unique machine-readable answer. Therefore a full normalization theorem is not yet well-posed as a theorem about accepted proof strings. The next exact grammar addition must specify, without altering weights: record bytes; assertion versus definition kinds; one root versus multiple selectors; DEF clause/row facets; LOCAL public/private paths; consumer typing; and source/auxiliary support accounting. Only then can a consumer-aware rule-by-rule polynomial compiler be proved or legally falsified.

**B3:** three candidate routes are refuted; actual noncircular same-`R_mix341` B3 remains OPEN. P versus NP remains OPEN.
