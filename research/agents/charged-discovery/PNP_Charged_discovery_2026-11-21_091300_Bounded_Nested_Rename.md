# T5-NESTED-RENAME-DEPTH1: fixed-depth nested authenticated renaming

## Claim and quantifiers
For each fixed integer d>=0 and each fixed deterministic solver A whose actual execution uses the authenticated typed-DLDD rules below with maximum *renaming-view dependency depth* <=d, for every source instance x of the explicitly encoded strict symmetric-C T5 NAND graph image, let W>=1 be the total charged bit-machine steps and v the normalized graph-variable count. The semantic DAG expansion of every resolved target has size <= c_(A,d)(W+v+1)^(d+1), and the cumulative shortcut completion cost, including final target closure, is <= c'_(A,d)(W+v+1)^(d+2). Consequently its positive-part cumulative shortcut defect is bounded by the same quantity. Constants are independent of x. The exponent depends on fixed d; **this is not a uniform polynomial when d grows with N**.

The strict-C relation consists of all permutations of 012,123,234,340,401. The ordered R relation is different. For the NAND image, n=v+5, m=v+e+5 and N=n+1+2 floor(log2(m+1))+1+3m ceil(log2(n+1)). The source has ten anchor frames and count 10 #IS(G). All instances in this image are SAT. No decision lower bound follows.

## Architecture and paid authentication
Each of at most O_A(W+v+1) created records is an ordinary typed DLDD node (constant, literal, valid decision, NOT, or binary decomposable operator), or a lazy view (base record ID, explicit variable bijection and authenticated source equality). Native records may point to earlier view records. A view may point to an earlier composite including views, hence nested reuse is genuinely admitted. The graph of dependencies is acyclic, actual shared IDs are retained, and the maximum number of view edges along any dependency path is d. Native operations must preserve the declared DLDD typing and scopes. Renaming is a bijection of the complete declared scope, including free variables; mapped source equality is checked by exact source data, not by hash or scalar-count equality. A scalar-only final oracle is not a permitted operation. All base construction, source parsing, map discovery and failed candidates, normalization, authentication, adaptive parameter selection, actual accesses, addresses, cache retention, bit arithmetic, deletion/recomputation and final output are paid in W. No free advice or preloaded variable-size templates. This is a restricted architecture, not a claim that every counter follows it.

## Proof
Let M be the number of distinct created records, including the O(v) free initial literals. M<=c_A(W+v+1). Expand each target view by copying its referenced typed DAG with the composed bijection, memoizing by the pair (original record ID, accumulated map) within the expansion. For any fixed sequence of at most d view-edge choices, there are at most M^d such sequences; for each sequence there are at most M native record identities. Hence the number of expanded records is at most sum_(j=0)^d M^(j+1) <=(d+1) max(1,M)^(d+1). Native sharing can only reduce this count. Bijections preserve decision-variable absence, decomposability, scope cardinality and count. The semantic expansion therefore exists and has the asserted size. There are at most M actual shortcut events, each requiring no more than this expansion size in the conservative completion ledger. Summing gives <=O_d(M^(d+2)); a final target-resolving event is included. Native progress is charged to native work. Positive-part defect is at most total extension cost. This proves the stated bounded-depth result.

The proof counts an intentionally loose set of paths and does not assume physical copying by A. Repeated uses of the same source record may share one physical record. If an expansion map is only represented as a chain, composing it is part of the *hypothetical completion* cost, not a free physical action; physical discovery/evaluation is separately charged. Full source authentication is a premise of the accepted shortcut. The proof does not claim efficient discovery of isomorphisms, nor that a compact scalar algorithm necessarily exposes such records.

## Falsifiers / controls
1. A well-typed depth-d DAG with more than M^(d+1) distinct (record, view-path) expansion contexts up to a d-dependent constant.
2. An authenticated bijection changing the full scoped predicate or count, including unused variables.
3. An accepted final scalar with no typed target derivation, or an accepted source equality based solely on hashes.
4. A size-dependent template, map or source identity supplied without charged construction or verification.

Affine/Tseitin, parity, forced-domain, complement, private-leaf and relocation controls are NOT claimed to be hard. They may be cheaply handled by algorithms outside this architecture. Variable renaming does not turn an affine scalar shortcut into a DLDD handle.

## Resource ledger and cap comparison
The execution's W charges source parsing, authentication, discovery, failures, adaptive switching, DAG node creation, access and addressing, arithmetic, storage, recomputation, and output. The completion bound is a semantic witness-representation *simulation*, not physical memory or actual runtime. For a sole-tape fixed A under T<=K N^a, a>=1, physical S=O(N^a), physical CM=O(N^(2a)), minimum-description CM=O(N^(a+1)), and count-map circuit size O(N^a log N). Since v<=N, the present restricted architecture gives L(F)=O_(A,d)(N^(a(d+1))) for the final diagram, and cumulative completion <=O_(A,d)(N^(a(d+2))). These are upper ceilings on a restricted compiler's witness expansion, not unconditional lower bounds. No exponent-uniform conclusion follows as d grows.
