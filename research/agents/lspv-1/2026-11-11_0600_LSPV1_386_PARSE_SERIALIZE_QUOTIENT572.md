## Theorem 572.1: full original /386 accepted-byte normalization

Let \(C_{386}\) mean **the actual complete Node CLI** on a single input, including \`checkProof(dat,{control:true})\`, its eleven synthetic negative tests, and parsed in-band source \`spec\`. Let \(W_{386}(\mathbf b)\) be the exact accepted logical charge \`summary.paid_total\`, equal to the number of RES records plus the number of globally distinct paid gate owners. Then

\[
\forall\mathbf b\in\{0,\ldots,255\}^{*},\quad
C_{386}(\mathbf b)=\mathrm{ACCEPT}
\Longrightarrow
\begin{cases}
C_{386}(N(\mathbf b))=\mathrm{ACCEPT},\\
W_{386}(N(\mathbf b))=W_{386}(\mathbf b),\\
\mathrm{Obs}_{386}(N(\mathbf b))=\mathrm{Obs}_{386}(\mathbf b),\\
N(N(\mathbf b))=N(\mathbf b).
\end{cases}
\]

Here \(\mathrm{Obs}_{386}\) consists of the decoded, checker-observed fields: graph spec, charge vector, guard, paid gate-owner tuples, each chronological record's kind, clause, ordered Resolution parents and pivot or SOURCE index or DEF gate as appropriate, and all summary counters. \(\mathrm{Obs}_{386}\) is *not* a raw-lexeme hash.

**Proof, exhaustive field guard analysis.**

1. On acceptance, every clause literal is a nonzero \`Number.isSafeInteger\`, every DEF gate-owner tuple contains only safe integers, and every parsed RES parent is an integer \(0\le j<i\) with \(i\) below the finite records-array length. A RES pivot is an integer actually present in the opposite-polarity parents; therefore it is necessarily a *safe integer* as well, even though the code checks \`Number.isInteger\` rather than \`Number.isSafeInteger\` directly. Parsed SOURCE IDs are \(-1\) or members of the numeric vertex-key map, and DEF facet IDs must be existing safe paid IDs. The \`spec.edges.length=3h/2\` check together with JavaScript's finite array-length bounds makes accepted \(h\) and vertex indices safe. Charge bits are exactly 0/1. The required original SOURCE \`[guard]\`, which passes \`clean\`, forces the guard to be a safe integer. Accepted summary counters equal actual finite array counts. Thus **no checker-observed proof ID, source ID, parent, pivot, gate, charge, cost or original graph integer can be nonfinite**. (Extra *unobserved* JSON fields can contain nonfinite numbers.)
2. ECMAScript JSON.stringify followed by JSON.parse returns the same finite binary64 Numbers and UTF-16 strings at every observed field. The only exceptional numeric reserialization of accepted observable data is negative zero to positive zero; all relevant checks use ordinary equality, comparisons, Map lookup and array indices under which signed zero is indistinguishable. JSON.parse has already resolved duplicate decoded object member names before either verifier runs. JSON.stringify retains the surviving property values and properly escapes lone surrogate strings, without independently transcoding identifiers.
3. Any \(Infinity\), \(-Infinity\) or otherwise unusual metadata occurring outside the observed fields can become \`null\` without affecting \`checkProof\`. None of its eleven mutations inspect such metadata; each mutation changes a specifically observed field. Property order and whitespace similarly have no effect. The original gate-owner Map, clause checks, strict RES transitions, source requirement, graph-model controls, paid counters, sink and eleven synthetic checks therefore take the same path and verdict.
4. The serialized output has a unique deterministic JSON representation of the parsed value, and a subsequent parse/stringify cycle makes no further changes to observable or unobserved JSON-serializable data. In particular, transformed nonfinite metadata is already \`null\`. Hence \(N^2=N\). The accepted logical paid work, owner identity set and shared DAG are unchanged. QED for the actual pinned archived /386 program.
