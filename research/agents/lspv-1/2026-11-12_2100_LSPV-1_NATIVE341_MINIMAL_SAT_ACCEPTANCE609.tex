\section*{An independent 12-vertex source and algebraic SAT proof}
Take a $K_4$ with one edge subdivided (five vertices) and a $K_{3,3}$
with one edge subdivided (seven vertices), and join the two degree-two
subdivision vertices by one bridge. Every vertex is cubic and the graph
has $V=12$, $E=18$. Number the three incident edges at vertex $v=5$ as
$0,1,10$, selecting the $10$ edge on a cycle (removing it leaves the
graph connected); bridge edge $17$ joins vertices $4$ and $11$.
Use odd charge $c_0=1$ and $c_u=0$ for all other vertices.
At each $u\ne5$ the four signed three-clauses encode the usual
local GF(2) equation
\[
 \bigoplus_{e\ni u}x_e=c_u.
\]
At vertex $5$, replace the four forbidden assignment patterns with
the genuine source condition
\[
 x_0\oplus x_1=0,
\]
which does not constrain $x_{10}$. Every clause remains an actual
signed three-literal SOURCE occurrence, and all 48 SOURCE occurrences
are ancestors of the checker's final paid DAG.

Let $B$ be the ordinary graph-incidence matrix over $\mathbb F_2$.
Because $G-\{10\}$ is connected, the columns other than column 10
span the even-parity subspace of $\mathbb F_2^{12}$, of rank 11.
Changing row 5 by deleting its coefficient for $x_{10}$ replaces column
10 with a unit column at the other endpoint of edge 10. That column has
odd coordinate sum, lies outside the even subspace, and raises rank to
12. Thus the modified source system is consistent for \emph{every}
charge vector and, in this instance, has exactly
\[
 2^{E-V}=2^{18-12}=64
\]
Boolean models. An independent complete $2^{18}$-assignment enumeration
confirms this count and the explicit witness above. It also supplies
39 actual single-clause-deletion witnesses; the remaining nine entries
are correctly null. The graph has a bridge, so the original checker
does not demand all 48 clauses be deletion-essential.

\section*{The exact accepted-byte/type-coercion failure}
The checker uses the condition
\texttt{parity !== f.charges[v]} to validate each local source
forbidden pattern. The packet's vertex-5 charge is the string
\texttt{"0"}, rather than numeric 0. Bitwise XOR in the independent
total-charge check coerces it to zero, but strict comparison of a
numeric pattern parity to the string \texttt{"0"} always succeeds.
This admits the four local patterns representing $x_0\oplus x_1=0$.

The terminal vertex-5 AND3 inference is node \texttt{d17}. It has
actual parent-union support $[0,1,10]$, but supplies the string
\texttt{"102"} as \texttt{support}. The implementation checks
\texttt{support.length} and \texttt{new Set(support).size},
then uses \texttt{support.includes(e)} on numeric edge indices.
JavaScript string inclusion converts numbers to strings, so
\texttt{"102".includes(10)} is true, as are the 0 and 1 checks.
However indexing the string in the truth-table loop yields the
\emph{characters} \texttt{"1"}, \texttt{"0"}, \texttt{"2"}:
edge 10 is left fixed at zero. Consequently the checker evaluates
the local conjunction only on the slice $x_{10}=0$ and incorrectly
validates the full global affine row
\[
 x_0\oplus x_1\oplus x_{10}=0
 \qquad (\texttt{mask=0x403}),
\]
although the real source permits models with $x_{10}=1$.
Eleven subsequent exact XOR operations cancel the falsely certified
rows and produce \texttt{mask=0x0,rhs=1}.
This is an \emph{accepted but semantically invalid} source-bound
fixture certificate, not a legitimate proof shortcut.
