\begin{theorem}[Original-/386 raw core-to-CLI closure]

accepts. Write $s=P.\mathrm{spec}$ for the parsed in-band source and
$g$ for its declared number of distinct paid AND2 owners.
Then there exists a deterministic UTF-8 raw certificate $b'$ for which
\[
\operatorname{CLI}_{386}(b')=\mathrm{ACCEPT},
\quad s(b')=s(b),
\quad W(b')=W(b)+\mathbf{1}_{\{g=0\}}.
\]
The original signed SOURCE records, all existing paid owners,
DEF facets, strict Resolution records and whole shared derivation
DAG are preserved, except that the final Resolution parents can be
reordered simultaneously with pivot negation.
\end{theorem}

\begin{proof}
The core loops over integer record indices $i$ while
$i<P.\mathrm{records.length}$, validating $P.\mathrm{records}[i]$ and
appending its clause to \texttt{known}. The final checks force the number
of visited rows to equal the integer
$n=P.\mathrm{summary.live\_records}>0$ and its last clause to be empty.
Consequently even an original-core-accepted ordinary JSON object
with numeric keys and coercive length properties has exactly the
checked rows $r_0,\ldots,r_{n-1}$. Replace any such object by a
genuine JSON Array containing these checked rows, without
changing their indices, parent references or clauses.
The original core also requires its gate declaration iterable
to consist of four-entry Arrays, so every accepted gate list
is already an Array.

When $g=0$, write $E$ for the original edge-variable count
and $t$ for the source guard.
Add one declaration $[0,z,1,2]$ with $z=E+1$ except when
$t=E+1$, when $z=E+2$.
The original accepted source has $E\ge6$, no earlier paid owner,
and a safe finite source-edge Array. Thus the declared fresh
output is a safe non-guard variable and its two inputs are
legal original edges. Increase each of the checked
\texttt{paid\_gates} and \texttt{paid\_total} counters by one.
No old proof record mentions this output and no old inference changes.

The last accepted empty clause must be a strict Resolution
conclusion. If its pivot is $+999999$, negate the pivot and
swap its two ordered parents. The first parent now contains
the new positive pivot and the second contains its complement,
yielding the same empty strict resolvent.
The last record has no consumers, so no older inference is changed.
This operation is cost-free.

The result passes the original core, has a genuine Array
records field, at least one paid owner and a final pivot
different from $+999999$. These are precisely the missing
full-CLI conditions established by the corrected original
eleven-mutation analysis of LSPV-1/577. Hence the unchanged
original complete CLI accepts its JSON serialization.
Only the new paid owner, if needed, increases $W$.
\end{proof}
