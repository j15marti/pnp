\section*{Why only this case is missing (argument, same skeleton rules as H0839)}
Take a shortest eight-step program for a target $f$; all its steps are live. Its last step writes $r_0$ (H0839 renaming). Operand cases for that step: (input, input) or (input, $r_1$) would leave the prefix's last write dead unless that write went to $r_1$, and then renaming $r_0\leftrightarrow r_1$ in the prefix turns it into (input, $r_0$) with no change of value; (input, $r_0$) of AND/OR type cannot give a target (H0624's vanishing check); (input, $r_0$) with XOR was probed by \texttt{tgt8} when the prefix uses all five inputs, and if $g=f\oplus x_k$ does not depend on $x_k$ then $C(g)\le C(f)-1=6$, $g$ is a four-input function, and the H0228 result $L=C$ on four inputs (\textbf{COMPUTATIONAL}) gives $L(f,2)\le7$, so no target arises that way. What remains is $\mathrm{op}(r_0,r_1)$ after a prefix that is fully live from the pair of final register values. This status is \textbf{CANDIDATE}: the argument is short but not machine-checked against an unreduced search on five inputs.
