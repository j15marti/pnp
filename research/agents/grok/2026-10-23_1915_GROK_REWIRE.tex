\section{Defect: free reuse of dying nodes (fixed)}
In \texttt{rewire2.py} the dry run treated any structural-hash hit as cost~0. On the pass-4 instance (random 5-input AIG, 10 steps, seed~6, output \texttt{0xaa00ff55}) the first positive-gain cut was $(5,6,8)$ with MFFC $\{9,7\}$ and estimated cost~1, but the ``existing'' gate it hit was node~7 itself, which the rewrite deletes. The pass applied it with estimated gain~1 and real gain~0, then stopped. \texttt{rewire3.py} (\texttt{82d20e1c62e0ba03}) maps the MFFC into the new graph and charges every hit inside it, plus its transitive fanin inside the MFFC. The same instance now goes $5\to3$, which is optimal. The width-5 pass got the same fix.

\section{NPN-keyed width-5 library (COMPUTATIONAL)}

A stored configuration is a minimum circuit for the canonical representative and is instantiated through the inverse transform. Each transform used for the first time on a key is verified by simulation (assertion), and all 42 runs in every variant preserve the output function (\textbf{0} mismatches). The fixed cost model alone \emph{loses} several pass-4 results (for example 4 $\to$ 30 for $m=1$). Pass~4 reached them partly through rewrites whose real gain was zero, which acted as accidental perturbation. Two principled replacements recover them. The \emph{PI cut} adds, for every node whose structural support has exactly 5 primary inputs, that support as a cut (the 12-cut limit had been dropping it). \emph{Zero-gain moves} accept a replacement with gain~0 and at least one new gate, stopping after 3 flat rounds. With both, 17 of 18 chains reach $4m$; the 18th (\texttt{0xf050d05}, $m=3$, seed~0) stalls at 32. The PI cut only helps nodes in the first block, because later blocks depend on the carry, not only on primary inputs. Rerunning that instance alone with a 30\,s SAT budget (0 timeouts, 77 functions synthesized) still ends at 32, so the stall is a cut-coverage or search limit, not a SAT timeout.
