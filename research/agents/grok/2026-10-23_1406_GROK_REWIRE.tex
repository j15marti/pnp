\section{Literature (brief, primary)}
\begin{itemize}
\item \textbf{DAG-aware AIG rewriting (KNOWN THEOREM / engineering).}
  Mishchenko, Chatterjee, Brayton, DAC 2006: precomputed AIG replacements for $K$-feasible cuts (typically $K{=}4$), keyed by Boolean function / NPN class; ABC \texttt{rewrite}/\texttt{resyn2}. This is the closest industrial analogue of a REWIRE library, but it is a synthesis heuristic, not a Circuit-SAT lower-bound theorem.
\item \textbf{NPN classification / Boolean matching.}
  Mishchenko--Chatterjee--Brayton style NPN libraries: 222 NPN classes on 4 inputs; practical rewriting uses a sparse subset. Fast NPN matching: Mishchenko et al., ICFPT 2013. Influence-aided exact NPN: arXiv:2308.12311 (2023).
\item \textbf{Minimum-structure libraries.}
  Enumeration of minimum fanout-free structures per NPN class up to 5 inputs (Mishchenko et al., IWLS 2019) for peephole rewriting.
\item \textbf{Memoization and Circuit-SAT.}
  Memoization as a lower-bound/algorithm technique goes back to Nechiporuk; recent \#SAT/threshold work (MFCS 2025) again notes that memoization needs a strong upper bound on the number of functions of a given size---exactly the growth question REWIRE must face.
\item \textbf{Gate elimination as rewriting.}
  Carmosino--Dang--Jackman (arXiv:2602.17942, 2026): convergent term-graph rewriting formalization of DeMorgan gate elimination. Analogy only: REWIRE aims at a \emph{library} of remembered configs, not only local identities.
\end{itemize}
Cross-domain import class: \textbf{ANALOGY / CANDIDATE}. AIG/NPN libraries transfer as engineering templates for keys and growth control; they do not by themselves yield a Circuit-SAT time lower bound.

\section{Prototype (own code)}
Path: \texttt{/workspace/rewire\_pass1/rewire.py} (SHA256 \texttt{87bc6157370dfda3}\ldots), plus \texttt{rewire\_sat.py}, \texttt{results.json}, \texttt{results\_sat.json}.
Design choices against exponential growth:
\begin{enumerate}
\item Keys are NPN-canonical truth tables for $n\le 3$ inputs (exhaustive orbit min); $n>3$ uses raw TT keys and is \emph{not} stored wholesale.
\item Store only configs that \emph{strictly simplify} some observed cone (or seed minimals); non-improving configs are rejected.
\item LRU cap (\texttt{max\_entries}=128); unused entries evictable.
\item Discovery budget capped at $\le 2$ gates when searching for a smaller realization (avoids exhaustive 3-gate blow-up).
\item Sub-configs share the same NPN key space (one entry per class, not per embedding).
\end{enumerate}
