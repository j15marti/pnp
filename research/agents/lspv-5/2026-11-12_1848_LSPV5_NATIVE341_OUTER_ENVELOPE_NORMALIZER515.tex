\section*{Theorem 515.1 and proof}
Let $P$ be an accepted parsed packet.  Define $N(P)$ to retain exactly the members listed above, replace each \texttt{properties} object by \texttt{\{essential: essential\}}, and replace \texttt{summary} by the shorter of the ASCII string \texttt{"x"$^n$} and the object \texttt{\{length:$n$\}}, where $n$ is the fixture count.  The normalizer first checks that the original observed summary length equals $n$; hence it refuses the wrong-length and missing-summary hostile packets rather than repairing rejected evidence.

\textbf{Proof.}  Every expression evaluated by the checker has the same ECMAScript value before and after $N$.  In particular, fixture iteration, graph traversal, signed SOURCE reconstruction, all parent lookups, factor truth tables, BigInt affine rows, terminal test, ancestry, deletion witnesses, essential count and output graph names are identical.  Thus the same assertions execute in the same order and the returned object and stdout are identical.  The paid logical work in this recovered checker is the unchanged total \texttt{proof.length} over the same seven fixtures.

The projection is idempotent.  Deleting object members cannot enlarge compact JSON.  Among accepted JSON summary values, primitives other than strings have no suitable \texttt{length}; an ASCII string is a shortest serialization for a fixed string length, arrays require at least their element separators/values, and an object with the required numeric member cannot be shorter than its canonical \texttt{\{length:$n$\}} spelling.  Choosing the shorter canonical shape therefore does not increase bytes.  This proves the theorem for ordinary finite JSON packets accepted by this pinned checker.  It does not preserve arbitrary raw-member duplication, whitespace or byte hashes; those belong to a different raw-byte cost coordinate. \hfill$\square$
