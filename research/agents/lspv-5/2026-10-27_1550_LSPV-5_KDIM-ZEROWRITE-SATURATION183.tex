\section*{Executive status}
\textbf{PROVED/EXACT (restricted control family).}  For every fixed
$k\geq1$ there is one fixed deterministic finite controller with one two-way
sequential read-only input head and $k$ initially blank sequential work tapes
that decides an explicitly tagged $k$-dimensional DISJ promise with
\[
 D=W=0,\qquad S=k(B+1)=\Theta_k(m^{1/k}),\qquad C=2m,
 \qquad T=O_k(mN),                                    \tag{1}
\]
where $m=B^k$, $D$ is the number of actual work-symbol changes, $W$ the
number of formal work writes, $S$ the total visited work cells, $C$ the
crossings of a fixed cut in the central gap, and $N$ the physical input
length.  Thus the WRITE-TIGHT2 face $d+ks\geq1$ is attained at
$(d,s)=(0,1/k)$ on this tagged easy promise for every fixed $k$.

\textbf{FALSIFIED implementation, then repaired.}  My first simulator used
an unbounded host-side move log to undo a tensor lookup.  That is hidden
memory and cannot witness (1).  I removed it.  The repaired simulator reverses
each lookup solely from fixed-level delimiter states and the positions of the
$k$ charged work heads.  It passed all 12,005 rerun controls.

\textbf{RESTRICTED/OPEN.}  The construction is not the unchanged canonical
exact22 encoding, is not a full-SAT algorithm, and does not fill the
$0<d<1$ interior frontier.  It has no automatic RAM, FLMV, circuit, or ARC
transport.  Consequently $P$ versus $NP$ and ARC-EDGE-90 remain
\textbf{OPEN}.

\section{Falsifiers declared before the search}
The predeclared attacks were:
\begin{enumerate}
\item batching $B$ bits might fill the full curve $D\,S=\Theta(m)$;
\item buffer reuse might secretly incur $\Theta(m^2/S)$ changes because every
  overwrite and restoration to blank counts;
\item locating a source record might require an uncharged binary index or an
  unbounded stack;
\item even a matching promise algorithm might be mistakenly transported to
  exact22, full SAT, random-access RAM, or FLMV.
\end{enumerate}
Attack 3 found a real bug in the first executable: its Python move list was
used to choose the reverse motion.  The final construction below eliminates
that list.  Attack 2 blocks the naive interior batching proposal: a
$B$-cell writable buffer reused for $m/B$ batches performs $\Theta(m)$
actual symbol changes in the worst case, not $m/B$.  No interior matching
construction was found.  Attack 4 remains a hard scope barrier.  The positive
result is the fixed-$k$ zero-change endpoint only.

\section{Exact model, promise, and quantifiers}
Fix $k$ once and for all; it is not part of the input.  The machine has one
two-way read-only sequential input head, $k$ initially blank semi-infinite
work tapes with detectable left ends, one head per work tape, fixed finite
state, and a fixed finite alphabet.  Every transition, input-head move,
work-head move, visited work cell, formal write, and actual symbol change is
charged.  There is no output head, index tape, random access, nonblank advice,
or growing state set.

For $B\geq1$, let $m=B^k$.  Alice's and Bob's bit vectors are indexed by
$[B]^k$ and recursively serialized.  Level $j<k$ uses its own delimiter
$\delta_j$; leaves contain the $B$ bits of the last coordinate.  The input is
\[
 {}^{\wedge}\operatorname{enc}_k(a)\ \#\ X^{8m+1}\ \#\
 \operatorname{enc}_k(b)\ \$ .                       \tag{2}
\]
The decision predicate is
$\operatorname{DISJ}(a,b)=1$ iff no coordinate has both bits one.  The
tagged representation has $N=\Theta_k(m)$; finite-state padding to
$\Theta(m\log m)$ changes no exponent.  Such padding still does not make the
language canonical exact22.

The quantifier order is
\[
 \forall k\in\mathbb N_{\ge1}\ \exists M_k\ \forall B\ \forall a,b:
 M_k\text{ correctly decides (2) with (1)}.           \tag{3}
\]
It is not $\exists M\ \forall k$.  The delimiter alphabet and finite control
may depend on the fixed constant $k$.

\section{Log-free coordinate lookup}
Work-head $j$ stores coordinate $i_j$ as its distance from the left end.  An
odometer over the $k$ heads enumerates $[B]^k$.  A lookup starts at the left
end of one tensor and recursively descends its tagged hierarchy.

At an outer level $j<k-1$, while work head $j$ is positive the input head
scans to the next $\delta_j$, crosses it, and moves work head $j$ one cell
left.  When that head reaches zero, the controller enters the next fixed
level.  At leaf level it crosses one bit and decrements the last work head
until that head reaches zero, then reads the selected bit.

The crucial repair is structural backtracking.  At the leaf, the input head
moves left over bits and increments the last work head until the preceding
symbol is an outer delimiter.  At outer level $j$, it moves left to the
previous delimiter of a smaller level (or block boundary), incrementing work
head $j$ exactly when it crosses a $\delta_j$.  All other crossed symbols
leave work heads unchanged.  This is the inverse of the forward lookup.
Since the nesting depth is fixed $k$, unwind level and direction reside in
finite control; there is no stack, move log, binary address, or changed work
symbol.

\begin{lemma}[lookup invariant]
For each fixed $k$, lookup begins and ends at the same input location and with
the same $k$ work-head positions, returns the addressed bit when all
coordinates lie in $[B]$, and identifies the first overflowing level
otherwise.  It performs no work write.
\end{lemma}
\begin{proof}
Induct downward on the fixed hierarchy.  At a leaf, every forward bit crossing
is paired with one backward bit crossing, respectively decrementing and
incrementing the last head.  At outer level $j$, every forward
$\delta_j$ crossing is paired with the same delimiter on the backward scan;
deeper symbols do not affect head $j$.  A smaller-level delimiter or block
boundary uniquely terminates that unwind.  The inductive child returns to its
child boundary with all lower coordinates restored before level $j$ unwinds.
Thus both input location and all head positions are restored.  Reaching an
outer boundary before the requested delimiter, or a non-bit before the
requested leaf offset, is exactly coordinate overflow.
\end{proof}

\section{Endpoint theorem}
\begin{theorem}[fixed-$k$ zero-change tensor comparator]
For every fixed $k\geq1$, the tagged promise (2) has a deterministic machine
$M_k$ satisfying (1) on every input.
\end{theorem}
\begin{proof}
Start all work heads at zero.  Lookup the same coordinate in Alice and Bob;
the Alice bit is retained in one finite-control bit while the input head
travels to Bob.  Reject if both bits are one.  Return to Alice and increment
the last work head.  Lookup detects overflow at a coordinate; reset that head
to its left end and increment the preceding head, exactly as an odometer.
Overflow at head zero terminates after all $m=B^k$ coordinates.

No work symbol is written, hence $D=W=0$.  Every head reaches positions
$0,\ldots,B$, so total visited work cells are exactly $k(B+1)$.  A complete
accepting comparison travels across the fixed middle cut once from Alice to
Bob and once back for every coordinate, hence $C=2m$.  Each lookup and
inter-block trip scans at most $O_k(N)$ input cells and moves at most
$O_k(N)$ charged steps.  Odometer operations add $O_k(mB)$ moves, absorbed by
$O_k(mN)$.  Therefore $T=O_k(mN)$.
\end{proof}

With $D=m^{d+o(1)}$ and $S=m^{s+o(1)}$, (1) attains
$d+ks=1$ at $(0,1/k)$.  This generalizes the independently checked LSPV-4
$k=2$ matrix control and the $k=1$ unary-head endpoint.  It establishes
shape sharpness for a tagged promise, not completeness or transport.

\section{Why naive batching does not settle the interior}
Suppose a one-work-tape algorithm stores a batch of $B=m^s$ source bits and
reuses the same cells for $m/B$ batches.  On adversarial data, writing the
first batch costs $\Theta(B)$ actual changes.  Replacing it by the next batch
costs $\Theta(B)$ in the worst case; clearing to blank and rewriting costs up
to $2\Theta(B)$.  Hence the total is
\[
 \Theta(B)\cdot\Theta(m/B)=\Theta(m),                 \tag{4}
\]
not $\Theta(m/B)$.  A formal same-symbol write can be ignored in $D$ but still
costs time; an actual overwrite or restoration cannot.  Thus batching does
not provide $D=m^{1-s+o(1)}$.

This is not a lower bound against all interior algorithms.  A representation
could reuse unchanged cells, encode differences, or exploit another source
structure.  The exact status is therefore \textbf{OPEN}, not falsified.

\section{Finite reproducible audit}
The log-free executable performed 12,005 checked runs: 5,724 exhaustive
ordered pairs on small configurations, 5,250 seeded larger random pairs,
1,026 diagonal accepting inputs with pairwise distinct fixed-cut histories,
and five full accepting scaling controls.  All passed.

For $m=256$, the controls gave: $k=1,B=256$, $S=257$; $k=2,B=16$,
$S=34$; and $k=4,B=4$, $S=20$.  Each had $C=512$ and $D=0$.  The
$k=3,B=6$ control had $m=216,S=21,C=432$; the $k=5,B=3$ control had
$m=243,S=20,C=486$.  Transition counts were between $9.76\times10^5$ and
$1.41\times10^6$, consistent with the deliberately slow $O(mN)$ scan.

The Python recursion represents fixed-depth compiled control only.  The
executable now retains no path log.  Host integers choose finite test inputs
and instrument counts; they are not granted to the simulated machine.

\section{Primary-literature check}
Petersen proves an equivalence between fixed multihead automata and bounded
counter machines on strictly bounded languages.  This independently supports
the general modeling fact that head positions carry counter information, but
does not prove the tensor theorem or any SAT transport:
\begin{itemize}
\item H. Petersen, ``Bounded Counter Languages,''
  \url{https://arxiv.org/abs/1204.0833}.
\item M. Holzer, M. Kutrib, and A. Malcher, ``Multi-Head Finite Automata:
  Characterizations, Concepts and Open Problems,''
  \url{https://arxiv.org/abs/0906.3051}.
\item F. C. Hennie, ``One-tape, off-line Turing machine computations,''
  Information and Control 8 (1965),
  \href{https://doi.org/10.1016/S0019-9958(65)90399-2}{doi:10.1016/S0019-9958(65)90399-2}.
\item D. Gajser, ``Verifying Time Complexity of Deterministic Turing
  Machines,'' \url{https://arxiv.org/abs/1307.3648}.
\item G. Pighizzini, ``Nondeterministic one-tape off-line Turing machines and
  their time complexity,'' \url{https://arxiv.org/abs/0905.1271}.
\end{itemize}
The latter three sources underscore that one-tape, multitape, deterministic,
and accepting-path measures are distinct.  None licenses importing a
one-tape crossing lower bound into the present $k$-work-tape model, or this
promise endpoint into random-access SAT.
