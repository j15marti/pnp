\section*{Pinned object and repaired restricted lemma}
Let $E$ be the number of original graph edges.  A SOURCE clause is interpreted
over coordinates $0,\ldots,E-1$.  Each AND3 record takes the union $S$ of its
three parents' supports, checks $|S|\leq 3$, enumerates every
$m\in\{0,\ldots,2^{|S|}-1\}$, and checks the asserted affine row on every
assignment passing the three parent tables.  XOR records combine rows by exact
BigInt XOR of masks and XOR of right-hand sides.  Parents must already exist,
and the final row is checked to be exactly the numeric pair $(0,1)$.

\paragraph{Lemma.}
For this program, suppose (i) SOURCE literals are ordinary signed safe integers
with the checker-authenticated incidences and forbidden parities, and (ii) each
AND3 field \texttt{support} is an Array.  If the checker accepts a completed
refutation, the source CNF is unsatisfiable.

\paragraph{Proof.}
For an AND3 node, the program checks equal length, pairwise distinct asserted
members, and inclusion of every numeric member of the computed union $S$.
Because the asserted support is an Array, these checks make it a permutation of
exactly $S$; no substring coercion is available.  As $|S|\leq3$, the shift
counts used to decode the local assignment lie in $\{0,1,2\}$, so ECMAScript's
modulo-32 shift rule cannot identify two positions.  Exhaustive local checking
therefore proves the asserted affine equation on every Boolean assignment
satisfying the three parents.

Project every mask to coordinates $0,\ldots,E-1$.  Extra high bits and sign
extension of a negative BigInt do not change this projection.  Exact XOR
preserves validity of the projected affine equations.  By chronological
induction, every accepted derived row is true on every source model.  The final
exact numeric row $0=1$ is false on every model.  Hence no source model exists.
\hfill$\square$

\paragraph{Scope warning.}
The proof does not validate the checker's actual unguarded language.  In that
language, a three-code-unit String can pass membership by substring coercion
and can misalign the enumerated assignment positions.  LSPV-1/609's satisfiable
packet is a genuine original-checker execution and must remain in a correct
CEGAR abstraction.
