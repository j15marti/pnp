from multiple checker components, every component must authenticate one
identical external source object in exact canonical bytes.

Thus the packet's two accepted namespaces concern incompatible sources:
one is SAT and one is UNSAT. This is not a refutation of a SAT source,
because no single checker connects the two namespaces.

\section*{Repaired exact-source join lemma}
Let \(y\) be a candidate packet, \(A_i(y)\) component-checker acceptance,
and \(S_i(y)\) the component's fully canonicalized source bytes, including
an explicit calculus/schema tag. For externally supplied source bytes
\(E\), define
\[
  J(E,y)\;:=\;\bigwedge_i\left(A_i(y)\wedge S_i(y)=E\right).
\]
Then \(J(E,y)\) implies, by exact equality rather than a cryptographic
assumption, that every accepted component is relative to the same \(E\).
The LSPV-3/578 packet fails this repaired join: its two canonical source
byte strings differ. Declaring the /341 source satisfies only the /341
side; declaring the /386 source satisfies only the /386 side; declaring
the empty source satisfies neither.

SHA-256 values in the raw evidence are telemetry only. They are not used
as proof-level identity, so no collision-resistance assumption enters the
lemma. The lemma is only an interface firewall. To obtain a completed
refutation, each component still needs a sound rule semantics relative to
the same \(E\); costs cannot be added across sibling checkers.

\section*{CEGAR interpretation}
The cheap abstract path was the conjunction of the two acceptances. It was
replayed concretely in both authoritative sibling checkers. Each component
acceptance is genuine and remains. Only the cross-source join is spurious,
because exact source bytes disagree, so refinement excludes only that join.

\section*{Literature and transfer audit}
Cook--Reckhow's proof-system framework treats a proof system as a sound,
complete relation to the formula proved; it does not authorize changing
the formula between verifier components. Cruz-Filipe et al.'s LRAT work
and the reference \texttt{lrat-check} interface take an input CNF together
with its proof, a directly transferable source-binding architecture.
Clarke et al.\ require abstract counterexamples to be checked concretely
before refinement, directly transferable to the acceptance-join replay.
Cousot--Cousot supplies the semantic discipline for relating concrete and
abstract executions, but not an \(R_{\mathrm{mix341}}\) cost theorem.

\begin{itemize}
\item \textbf{Directly transferable:} explicit formula-plus-proof checking
and concrete replay before CEGAR refinement.
\item \textbf{Analogy requiring a new theorem:} an LRAT-like source-bound
format covering SOURCE, Resolution, AND3, GF(2), LOCAL-CONVERT, paid DEF,
branch contexts, discharge, joins, deletion, and sharing in one historical
grammar.
\item \textbf{Failed transfer:} treating two source-independent checker
acceptances as one mixed proof.
\end{itemize}

Primary sources reviewed:
Cook and Reckhow, \emph{The Relative Efficiency of Propositional Proof
Systems}, JSL 1979; Cruz-Filipe et al., \emph{Efficient Certified RAT
Verification}, 2017; Clarke et al., \emph{Counterexample-Guided Abstraction
Refinement}, CAV 2000/JACM 2003; Cousot and Cousot,
\emph{Abstract Interpretation}, POPL 1977.
