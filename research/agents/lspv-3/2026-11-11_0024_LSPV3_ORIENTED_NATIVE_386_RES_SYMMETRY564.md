## Theorem 564.1: RES signed-port involution and exact accepted orbit (PROVED/RESTRICTED)

Let P be any complete packet accepted by the pinned original archived /386 function checkProof, with q RES records. A RES record has two earlier parent indices a,b, a nonzero signed pivot p, and normalized clause c, where p belongs to parent A and -p belongs to parent B and c is the strict non-tautological resolvent.

Define an operation tau_i at any RES record i:

$$
\tau_i:\quad ([a,b],p,c)\longmapsto([b,a],-p,c).
$$

All other bytes interpreted as fields are unchanged. Then for every subset S of the q Resolution records,

$$
\operatorname{Accept}_{386}(P)\Longrightarrow
\operatorname{Accept}_{386}(\tau_S P),
\qquad W_{386}(\tau_S P)=W_{386}(P).
$$

Every original SOURCE clause, signed defining facet, gate owner and globally fresh output wire is identical; every RES output clause and chronological record index remains identical. Therefore the terminal contradiction, the entire shared **unoriented** dependency DAG, paid-owner identity set and all record/price summary counters remain identical. The involutions act independently and commute. If each strict RES parent pair has two distinct indices (forced by the checker's non-tautological canonical clause requirement), the q elementary operations act freely on serialized RES parent/pivot fields and generate **exactly 2^q distinct accepted JSON record arrays** at fixed logical price and identical source.

**Proof.** Original source code checks RES arity two, both parent indices earlier than the current record, a nonzero integer pivot p, A.includes(p) and B.includes(-p), and exact equality of c with the canonical literal set formed from A minus p and B minus (-p). After exchange and negation, the corresponding tests become B.includes(-p) and A.includes(p), precisely the old checks in reversed order. The computed literal multiset is the same by commutativity of union. Canonical de-duplication and rejection of tautological resolvents therefore give the identical c. All subsequent nodes see exactly the same clauses at exactly the same parent indices, by induction on record order. The original gate_defs preprocessing, SOURCE/facet checks, graph/charge controls, source completeness and summary accounting depend on unchanged data. Thus checkProof accepts and the fixed price RES-count plus distinct global paid gate owners is unchanged. Each transformation has order two; distinct RES records are disjoint editable fields. A strict clean clause cannot contain p and -p, so the same clause cannot serve simultaneously as both complementary parents of that RES record; hence swapping the two **distinct** parent indices really changes their serialized order. Consequently all 2^q choices give different serialized record arrays. QED.
