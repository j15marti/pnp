\section*{Theorem: primitive identifier renaming equivariance}
For an accepted parsed /341 packet $P$, let $I(P)$ be the finite set of primitive keys used for all SOURCE IDs, paid inference IDs, parent references and deletion-source references. Let $\phi:I(P)\to J$ be injective under the implementation's Map/Set key equivalence, with all new keys faithfully representable by JSON primitives. Apply $\phi$ to every identity and reference occurrence, not to the original signed clauses, factor supports, affine rows, source order, rule opcodes, graph, witnesses or fixed weights.

\begin{theorem}[Restricted exact native-parser symmetry]
For the archived /341 checker,
\[
 \operatorname{Accept}_{341}(P)
 \quad\Longleftrightarrow\quad
 \operatorname{Accept}_{341}(\phi(P)).
\]
The paid-node identity graph, whole parent DAG and original SOURCE are isomorphic, with exactly the same paid work. This assertion concerns renaming of identifier \emph{fields}, not a free inference rule or historical Rmix341 closure.
\end{theorem}
\begin{proof}
SOURCE ID freshness is implemented by src.has and src.set on a JavaScript Map. The ordered proof loop checks byId.has(p.id), obtains parents through byId.get, compares their two IDs by strict inequality and inserts byId.set(p.id,p). The ancestor traversal uses a Set of the same keys. Under an injective consistent primitive-key replacement, each lookup, freshness test, distinct-parent test and shared ancestor test has exactly its original truth value. Inductively all factors, affine rows and terminal dependencies are unchanged. The deletion/source indexing predicate uses strict equality of the correspondingly renamed references. Signed incidence, SOURCE values, essentiality witnesses, graph properties, factor truth tables, fixed length $4V-1$ and terminal row are unaffected. Every original assertion therefore has the same outcome. Applying the inverse bijection on $I(P)$ proves the converse.
\end{proof}

Object-valued IDs are excluded: separate parsed JSON objects cannot share reference identity through independent encoded references. Noninjective numeric tokens are excluded, including binary64 collision cases already studied in LSPV-5/477. \section*{Typed-identity abstraction implication}
