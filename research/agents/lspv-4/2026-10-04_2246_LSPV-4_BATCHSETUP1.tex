\section*{Exact batching model}
Fix a source-matched typed edge $e:i\to j$ on parent length $n$. There are at most
\[
Q_e(n)=n^{\eta_e+o(1)}
\]
required child invocations, each of logical length at most
\[
m_e(n)=n^{\theta_e+o(1)}.
\]
The children are partitioned into at most
\[
D_e(n)=n^{\delta_e+o(1)},\qquad 0\le\delta_e\le\eta_e,
\]
setup classes. A class setup costs time $n^{p_e+o(1)}$ and retained workspace $n^{a_e+o(1)}$. Once the correct setup state is available, each logical child-bit access costs time $n^{g_e+o(1)}$ and transient workspace $n^{s_e+o(1)}$. Type $j$ runs in time $m^{C_j+o(1)}$ and workspace $m^{\rho_j+o(1)}$.

The partition into setup classes is not semantic bookkeeping. It must be computed or supplied by the source construction, and every child grouped into one class must use the same source-defined realization of the reusable setup state. Classification, indexing, transport, and construction costs are charged separately if they exceed the declared exponents.

\section*{PROVED/EXACT conditional accounting: batching interpolation}
If each distinct setup class is materialized once and reused for all children in that class, total setup time is at most
\[
n^{\delta_e+p_e+o(1)}.
\]
STREAMCOMP1 charges the child simulations by
\[
n^{\eta_e+g_e+\theta_e C_j+o(1)}.
\]
Therefore a conservative source-matched implementation satisfies the edge upper-bound exponent
\[
\boxed{
T_e(n)\le
n^{\max\{\delta_e+p_e,\ \eta_e+g_e+\theta_e C_j\}+o(1)}
}
\]
plus separately declared classification and transport costs. Equivalently the typed fixed-point ledger must include
\[
\boxed{
C_i\ge
\max\left\{
r_i,\,
\delta_e+p_e,\,
\eta_e+g_e+\theta_e C_j
\right\}.
}
\]

This exactly interpolates between two limiting cases. Independent setup for every child has $\delta_e=\eta_e$, giving setup exponent $\eta_e+p_e$. One globally reusable setup has $\delta_e=0$, giving setup exponent $p_e$. No intermediate saving is justified unless the source construction proves the corresponding bound on distinct SAME\_REALIZATION setup states.

\section*{PROVED/EXACT conditional accounting: retained-state alternatives}
If setup states are processed class-by-class and discarded before moving to the next class, depth-first workspace obeys
\[
\boxed{
\rho_i\ge
\max\{\sigma_i,a_e,s_e,\theta_e\rho_j\}
}
\]
plus address/index workspace. If instead all $D_e(n)$ setup states of size $n^{a_e+o(1)}$ are retained simultaneously without compression, their aggregate representation can require
\[
n^{\delta_e+a_e+o(1)}
\]
space, so the workspace ledger must include
\[
\boxed{\rho_i\ge\delta_e+a_e}
\]
for that implementation. This is an implementation-dependent upper-bound charge, not a lower bound on every representation. A compact shared data structure can beat the aggregate representation only if its construction, random-access evaluation, and SAME\_REALIZATION semantics are proved and charged.

\section*{Hostile controls}
\textbf{RECOMP.} Discarding a setup state trades retained workspace for repeated setup time. If a class is reconstructed $R$ times, the reconstruction multiplicity must be included in the time exponent.

\textbf{INTERP.} An interpreter can compress many setup states into one program, but its per-access decoding cost enters $g_e$ and its working state enters $s_e$ or $a_e$. Program length is not evaluation cost.

\textbf{DELAY.} Deferring setup until a child is actually queried can reduce realized setup count, but then the proof must use the realized count rather than the number of semantic possibilities. DELAY cannot be charged simultaneously as if all counterfactual classes were materialized.

\textbf{COPY.} Duplicating syntactic children can increase apparent multiplicity without increasing distinct setup states. Hence $\eta_e$ and $\delta_e$ must remain separate.

\textbf{Current-scale hidden call.} If setup, class identification, or bit generation invokes the original hypothetical SAT decider $A$ on length $n^{1-o(1)}$, the unknown exponent $K$ reappears in $p_e$, the classification exponent, or $g_e$. Batching does not erase that dependence.

\textbf{Semantic oracle.} A maximal semantic oracle can collapse setup and classification costs. Thus BATCHSETUP1 relativizes and is not a lower bound.

\textbf{Algebraic oracle.} Low-degree extension or product-span access may merge setup classes or accelerate generation. That is an algorithmic escape unless an independent source theorem forces costly acquisition. Algebraic structure alone does not imply a lower bound.
