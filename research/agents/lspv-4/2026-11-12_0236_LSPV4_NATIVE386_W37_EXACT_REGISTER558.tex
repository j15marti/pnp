\section*{Exact order-ideal theorem}
Write $V$ for the 34 paid RES occurrences, $D\subseteq V$ for an order ideal, $L(D)=\{u\in D:\exists v\notin D,\ u\to v\}$ for the paid live frontier, and $w(u)$ for the UTF-8 length of the compact canonical JSON array representing the signed conclusion of $u$. A ready node $v$ has every paid RES parent in $D$. Set
\[
r_v(D)=
 \begin{cases}
 1&\text{if some paid parent }u\in L(D)\text{ has no later consumer after }v\\
   &\hspace{.3in}\text{and, for nonexpanding overwrite, }w(v)\le w(u),\\
 0&\text{otherwise}.
 \end{cases}
\]
The required capacity at the operation is $|L(D)|+1-r_v(D)$; for fresh-output storage, $r_v(D)=0$. In this atomic model, a step must co-retain the previously live results and its output, except that an eligible last-used input's slot may be reused. This condition is necessary, and sufficient by explicitly assigning the chosen output to that slot. Iterating over all reachable ideals with this admissibility test is therefore a complete search over fixed-DAG schedules, not a greedy heuristic.

For a path $D_0=\emptyset,D_1,\ldots,D_{34}=V$, define its cumulative retention and compact clause-byte areas as
\[
A=\sum_{i=0}^{33}|L(D_i)|,\qquad
B=\sum_{i=0}^{33}\sum_{u\in L(D_i)}w(u).
\]
Dynamic programming maintains the lexicographically least $(A,B)$ at every reachable ideal. This is exact because every transition to the same ideal has the same future live frontier and ready operations. An independent Python executable with the full source packet and a separate JS ready-state reachability audit confirmed the following finite graph certificate:
