\begin{proof}

In the archived checker, numeric-array supports are indexed in their declared order; a permutation therefore computes the same parity with the same eight-bit table. For a three-character string of distinct single-decimal-digit coordinates, its length and the cardinality of its JavaScript Set equal three. For each required numeric coordinate $x$, the checker invokes string \texttt{includes(x)}, which first coerces $x$ to its single-digit string, so the original numeric-membership test succeeds. Its truth-table loop accesses the single-character strings by index and coerces those digit strings to the corresponding original-edge array indices. This again computes the same parity and passes the same affine mask/RHS test. All four changed factors have only XOR consumers, which use their unchanged affine rows, not the runtime type of the support. Other native SOURCE, DAG, parent, deletion and goal tests are unchanged.

For the other 242 genuine array-valued factors, the independently established typed support/table permutation transport of LSPV-3/594 preserves their original-edge truth predicates. Composition is valid by induction along the chronological shared DAG. The four terminal twelve-choice actions commute with all upstream typed transformations. Finally, the ASCII JSON array representation such as \texttt{[0,1,2]} has seven bytes while the string representation \texttt{"012"} has five; neither tables nor parent indices change. The local sorted-string mapping is consequently evidence-byte cost-nonincreasing and logical-work preserving. These are claims about \emph{accepted encodings}, not independent mathematical proof identities.
