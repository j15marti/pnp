## Theorem 523.1: exact paid-value space separation

Fix the original cubic odd-Tseitin /341 DAG for a connected cubic graph with V >= 4 vertices. Each vertex supplies four width-three original source clauses and three sequential binary AND3 operations to derive a 3-variable parity factor. A left-associated XOR chain joins the V parity rows to 0=1. There are exactly

$$
q=3V+(V-1)=4V-1
$$

**distinct unit-paid nodes**. Every nonsink paid node is consumed by exactly one later paid inference: the actual recovered paid sub-DAG is a rooted tree. It does not itself witness shared/reconvergent paid-lemma reuse.

Define *retained paid-value slots* by non-overwriting first creation: a node can be constructed only after all paid antecedents are present, and its result occupies a fresh slot before parents can be released; original SOURCE factors are separately available read-only leaves. Each paid node is computed exactly once. This is a logical computation-storage model, not an all-phase physical WORK-space bound.

**Theorem.** For the original producer order, immediate optimal last-use release has peak

$$
P_{\mathrm{producer}}=V+1.
$$

For a depth-first topological order on the same paid DAG, immediate optimal last-use release has peak

$$
\boxed{P_{\mathrm{DFS}}=3}
$$

and three is *globally optimal for this fixed DAG under the specified non-overwriting primitive*. Both have the same logical work q=4V-1, the same inference weights, the same reference identities, the same weighted critical-path span D=V+2 and the same complete JSON packet byte length. No paid recomputation occurs.

**Proof.** In the emitted order all V terminal vertex rows are constructed before the first XOR. At construction of the final vertex's next local AND3 node, the V-1 completed vertex rows and its previous paid local value remain needed, and the fresh output occupies one further slot; peak V+1. The release-after-last-use policy minimizes live nodes for a *fixed* order when recomputation is forbidden, proving equality. In the DFS order, finish two vertex chains and immediately produce the XOR result, discard both parents, then construct each subsequent vertex chain while retaining a single accumulator and immediately join it. Each local chain needs at most two paid values, and a join needs two parents plus one fresh output, hence peak at most three. At least one XOR has two distinct paid parents; that operation necessarily reaches three live paid values if it cannot overwrite either parent until after output creation. Thus the optimum is exactly three. The dependency DAG and node contents are unchanged, so total paid creations, longest dependency chain, source premises and JSON byte count are unchanged. QED.

**Primitive/model sensitivity:** In-place XOR updates can use two paid value slots, so the three-slot lower bound does not apply to a destructive-update model. Likewise the original Node checker retains a full JSON object and a byId map, so its **actual heap is not three slots** after reordering. The lower bound concerns a particular logical retention primitive only; other legal proof DAGs, balanced XOR joins, extension variables, algebraic shortcuts and recomputation schedules remain allowed when analyzing the true mixed minimum.
