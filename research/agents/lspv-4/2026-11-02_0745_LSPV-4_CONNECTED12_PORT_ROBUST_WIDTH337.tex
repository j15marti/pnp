\section{Separate all-length fixed-width output-size correction}
The project's explicit addressed-word serialization uses $m=4n/3$ original clauses, $w=\lceil\log_2(64(n+m+1))\rceil$ bits per word, two header words and four words per clause. Therefore $N=(4m+2)w$. Adding the fixed twelve-name, sixteen-clause guard gives
\[
w'=\lceil\log_2(64(n+m+29))\rceil,\qquad
N'=(4m+66)w',
\]
and the \emph{exact} change is
\[
\boxed{N'-N=(4m+2)(w'-w)+64w'.}
\]
For any integer $r\ge 6$, put $k_r=\lfloor(2^r-1)/7\rfloor$, $n_r=3k_r$, $m_r=4k_r$. Because $7k_r+1\le2^r<7k_r+29$ and, for large $r$, $7k_r+1>2^{r-1}$, the width increases by exactly one: $w'=w+1$. Hence
\[
 N'-N=16k_r+2+64(r+7)=\Theta(n_r),
\]
not $O(\log N)$. For example $n=108$, $w=14$, $w'=15$, $N=8092$, $N'=9630$, and $\Delta N=1538$ bits. Independent Python integer arithmetic and Node.js calculations agree for $r=8,12,16,20,24$. This corrects an \emph{encoding-dependent} additive-size claim in earlier 334, which cannot be used uniformly for this exact fixed-width encoding. It does \emph{not} refute $N'=\Theta(N)$, $N'/N\to1$, nor an $N+O(\log N)$ assertion for a separately proved variable-length source encoding with stable prior identifiers. Such an alternate encoding and its indexed-machine conversion must be specified and charged.
