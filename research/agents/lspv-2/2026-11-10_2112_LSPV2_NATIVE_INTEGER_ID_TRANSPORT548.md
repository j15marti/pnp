## Theorem 548.1, restricted identifier-transport lemma

Fix an accepted packet P of the pinned recovered verifier. Let I be the finite set of **actually referenced and explicitly present primitive source/paid identities**. Let f be a globally injective relabeling of I into distinct safe JSON integers; substitute f consistently at original SOURCE IDs, paid IDs, parent references and deletion-witness source IDs. Assume no collision with a separately retained missing-ID sentinel and that all other fields remain fixed. Then the original checker gives the same acceptance result, the source formula and derivation DAG are identical up to renaming, and each distinct paid node retains its original count-once logical charge.

Proof: inspection of the pinned verifier shows that IDs appear only as key identities in source/derived Map membership and lookup, parent pair inequality, source-to-deletion equality, reachability and final-parent reference. Distinct safe integers preserve each equality and disequality relation, and all semantic graph, signed literal, truth-table and affine-mask computations are ID-invariant. Therefore the same assertions are traversed with the same outcomes. The lemma is restricted to injective, stable primitive-key substitutions; it is **not** a normalization theorem for arbitrary nonfinite numbers, object keys, omitted *referenced* IDs, or the full unknown calculus.

A second operational lemma follows directly from code: an unreferenced terminal inference can omit its ID because byId.has(undefined) is false before first creation, byId.set(undefined,p) stores the terminal, and the verifier checks its kind and affine contradiction without requiring that a textual terminal ID be present. This does **not** authorize deleting a referenced interior ID or charging repeated identities more than once. A reference abstraction demanding every paid node have an explicit textual ID would exclude a genuinely accepted packet.

The two results concern accepted-byte and parsed-key behavior, not independent source binding or semantic soundness of every packet accepted by this historically flawed checker. LSPV-3/560's safer canonical-string subset remains valid as a deliberately smaller language; this run proves it is not the complete fixture accepted language.
