## IDEA, assumptions and falsifiers fixed before searching

Hypothesis: The LSPV-2/508 counterexample rules out replacing a guest's *entire* final memory with a cached anchor's poststate, but not a paid **frame-preserving write-effect replay**. In a deterministic fixed guest, a trusted execution records every immutable-input position read, every pre-first-write memory read (live-in), the last value written to each address, all guest-visible entry metadata, and the terminal metadata and label. A new caller agreeing on the live-in observations can inherit the guest's writes while retaining its own untouched memory.

Falsifiers: F1, a read-after-write is incorrectly treated as a live-in read, overrestricting reuse; F2, any dynamic write address or control path changes despite matching live-ins, invalidating the induction; F3, copying an entire old poststate rather than applying writes corrupts untouched private cells used by a later caller; F4, forged external traces or inherited historic WORK high-water are trusted or omitted without being separately authenticated and charged. The result is limited to trusted in-process deterministic traces, exact caller state, finite external controls, and full historical high-water ledgers.

## ITERATE: frame-preserving deterministic effect theorem (PROVED/RESTRICTED)

Let \`G\` be a deterministic finite-program guest with explicit immutable input and mutable WORK cells. Fix equal guest-entry control/register/head/index state and equal immutable-input length. Let an authenticated execution on input \`x\` and initial memory \`M\` terminate, producing label \`b\`, ordered input-read pairs \`Q\`, the **read-before-first-write** memory map \`L\`, a last-write map \`V\`, terminal control/register/head/index metadata \`z\`, and guest WORK-read high-water \`h\`. If another input \`y\` agrees with \`Q\` and its initial memory \`M'\` agrees with \`L\`, then the *entire transition trace* has the same operations, write addresses and read values. Its exact terminal memory is

$$
M'_{\mathrm{out}}(a)=\begin{cases}V(a)&a\in\mathrm{dom}(V),\\M'(a)&a\notin\mathrm{dom}(V).\end{cases}
$$

The label is \`b\`; the terminal metadata is \`z\`. Its whole-run WORK high-water is **at least** the max of the caller's ancestral historical high-water and the guest's \`h\`, and all wrapper/replay reads and writes are separately charged. No independent caller-private cell outside \`dom(V)\` may be replaced by the anchor's value.

**Proof.** Induct on deterministic guest transitions. Before the first guest operation, control, registers, and head/index metadata agree. At each immutable-input read, the observed bit agrees by \`Q\`. At each WORK read of address \`a\`, either the address was already written, so equal earlier deterministic writes give equal values, or it was not yet written, so \`L(a)=M'(a)\`. Thus all transition predicates and dynamic addresses agree. Every write value and address consequently agrees, so the anchor's last-write map gives the target terminal memory *only on written cells*. Untouched target cells retain their own initial values, establishing the displayed frame equation. All guest read addresses match and so does its guest-only high-water, but an ancestral peak remains. QED. This standard effect/frame argument does not prove fast discovery of the certificate.

**Limits / certificate provenance.** The theorem requires a **trusted** original execution under the exact guest code and representation. An untrusted external effect record is neither a SAT oracle nor an accepted R_mix341 proof. The minimal proof is semantic; actual caching additionally pays trace construction, saved read/write evidence, lookup, storage, mutation checks, replay, and inherited index/WORK high-water. If there are \`r_i\` input reads, \`r_m\` live memory reads and \`w\` distinct writes, a direct explicit indexed log needs \`O((r_i+r_m+w) log(H+N+2))\` bits plus values/metadata for maximal accessed address \`H\`, and each reuse costs \`Omega(r_i+r_m+w)\` accesses before indexing overhead. No upper bound \`<=N^(1/2+o(1))\` on these quantities follows for all polynomial SAT guests, and no child decomposition, same-machine compiler or recursive applicability has been produced.
