## Theorem 464.A: non-index-jumping index-tape cleanup (PROVED/RESTRICTED)

Fix any deterministic FLMV random-access Turing machine `A` with a finite, fixed number `K` of associated index tapes. Each index tape is an ordinary sequentially accessed tape; only the associated **non-index** tape has an indexed head jump, which erases its index tape. At the start of a guest invocation every index tape and index head are initialized to blank and position 0. Let its actual guest trace contain `T` native transitions. Let `H_i` be the maximum nonnegative index-tape head position reached on index tape `i`. Then

$$
H_i\le T,\qquad \sum_{i=1}^{K}H_i\le KT.
$$

There is a direct legal cleanup using no indexed non-index work-head jump which returns **every index tape** to blank with its head at 0 in

$$
O\left(K(T+1)\right)
$$

native steps, with zero increase in the maximum **guest non-index work-tape** address. The cleanup controller needs O(K log(T+2)) charged work bits to record each `H_i` and the current index-head location. Updating those counters in the instrumented execution requires O(KT log(T+2)) extra native transitions using fixed extra tapes. For fixed A, K is constant. Therefore the instrumented guest plus index-tape cleanup costs O(T log(T+2)) time and O(log(T+2)) extra charged working bits, aside from the guest's own work and any other compiler phases.

**Proof.** From the initial index-head position 0, an index head can move by at most one cell per native transition. Every index position potentially written lies in the finite interval [0,H_i], including cells to the right of the final head. After the guest halts, move that index head left to 0 without invoking an associated non-index indexed jump; sweep all cells 0,...,H_i, overwriting every nonblank symbol with blank; move the head back left to 0. This needs at most (current position)+2H_i+O(H_i+1) moves/reads/writes, hence O(H_i+1). Index tapes do not contribute to the original FLMV work-space measure; no reset step indexed-moves the associated non-index work head, so no exponential high-water address can be visited as a reset side effect. Track H_i and index-head position in binary on ordinary charged work tape; each counter update costs O(log(T+2)). The original machine has fixed K. QED.

**Tightness (within direct raw restoration).** A guest can visit L index cells, write one 1 in each, and execute no non-index indexed jump, using T=2L-1 native moves/writes and constant non-index work high-water. A reset that does not perform a non-index indexed jump must overwrite L cells, requiring Omega(L)=Omega(T) transitions. LSPV-4/462 additionally proves that attempting a single native erasing jump subject to polynomial work high-water must first clear Omega(L) high bits; jumping immediately would visit work address 2^L-1. Thus Theta(T) is tight in worst-case raw index restoration at polynomial work high-water.

**Exact scope.** The theorem repairs ONLY INDEX-TAPE reset charges; it does not account for non-index DATA/MARK cleanup, guests with arbitrary output semantics, virtual guest input reads, source authentication, source decompositions, work tape high-water, malformed-input logic, or recursive closure. It cannot be substituted for a full same-machine guest interpreter. In particular, earlier LSPV-4/461's O(M polylog N) clearing of dirty DATA/MARK work cells remains distinct: here the index-tape term is O(T), and the guest plus full reset needs both terms plus all other charged phases.
