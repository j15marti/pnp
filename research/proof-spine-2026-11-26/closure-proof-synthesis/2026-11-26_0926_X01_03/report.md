## 1. Fixed-polynomial budget theorem
Given original encoded N, uniform total-time cap O(N^C), fixed per-state work O(N^a), one enumeration of binary rank g fits if 2^g <= N^(C-a), equivalently g <= (C-a)log2 N. For at most N^d identical worst-case calls use g <= (C-a-d)log2 N. For q-ary independent coordinates replace base2 by q, and for nonuniform calls require sum_i q_i W_i <= fixed polynomial where W_i is an actual upper bound on all per-state work. There is no largest fixed C defining P. Arbitrarily large fixed exponents allowed, exponent may NOT grow with N or instance. Constants/overhead included in asymptotic ledger; no practical speed claim.
For recursive potential n^c (integer positive n, fixed c), if q paid children of size <=s, q s^c <= n^c-1 suffices; more generally sum child potentials <= parent-1. Then at most initial potential many nodes including terminal nodes (inductively subtree work in units of paid nodes <= parent potential), each with charged polynomial overhead in original N. If there are additional attempts/queries/children count them as well. A mere bound on number of retained states does not charge discovery of all rejected candidates. Independent factor decision costs add, not multiply. Counts of all global assignments can be exponential in value but bit length polynomial; computing them is a different problem.

## 5. Exact counting is stronger than needed, even on forest
Valiant, "The complexity of computing the permanent", TCS 8 (1979)189–201, Theorem1, https://doi.org/10.1016/0304-3975(79)90044-6, primary https://core.ac.uk/download/pdf/82500417.pdf pp189–190. Permanent of 0/1 matrix #P-complete (standard polynomial oracle reduction notion). Even unguarded matching-grid exact solution count equals permanent by prefix bijection. Stronger same-source control: for arbitrary n x n center availability, attach a private 2x2 variable block to each distinct physical row prefix bit E(i,j), 0<=j<n-1, with equality guard to its first-col prefix. The guard incidence graph is a tree (center--guard--leaf for each port); every PM determines all prefix bits and uniquely lifts all leaves; distinct PMs differ in at least one prefix. Therefore counting distinct attainable full guard patterns is #P-hard even on these tree charts (indeed bijection, #P membership on this family). Forest decision is polynomial and does not require exact count. No claim #P-hardness implies P!=NP, and general projected counting may have a different complexity class. Key distinction: capped enumeration of polynomially many relaxed patterns via polynomial prefix oracle is safe; arbitrary exact total counting is not known polynomial. Counting parity alone may cancel even nonzero counts; no arithmetic shortcut assumed. No need for external VP/VNP premises.
