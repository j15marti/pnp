## 1. Single-receiver weighted assignment (SRWA, PROVED)
Partition original tuple IDs and owner IDs into regions. Every Y and Z incidence remains inside its tuple's region; every crossing incidence is X. Each region has equal numbers s of X,Y,Z owners. Every incoming X incidence in a given region attaches to ONE actual X owner r, though that owner may have arbitrary degree. Regions with no incoming edge permitted. Let the directed arc e be the original tuple's crossing X incidence, from tuple region to its X owner's region. Exactly one arc per crossing tuple, retain its actual ID; parallel arcs permitted. Balance gives number of outgoing selected arcs = number of incoming selected arcs: Y counts exactly s selected tuples in each region; subtract internal X incidences from the local X occupancy s. Incoming arcs all use owner r, hence at most one can be selected. Therefore local choices are exactly inactive (no crossing selected) or active (one outgoing arc e, one incoming arc). For a fixed outgoing e the set of feasible local assignments and their cost depends ONLY on whether incoming count is one, not the identity of the incoming arc. This holds for all original tuple literal guards: incoming tuple IDs are outside this region and enforced where those tuples originate; all incoming arcs supply identical occupancy to r. No claim for coupled nonliteral external guards without verified adapter.

Acquire exact inactive response c_a(0) by forbidding all outgoing tuples and solving all local exact-one rows. Acquire response c_a(e) by pinning e, forbidding other outgoing tuples, setting incoming owner r target zero, and solving all other local rows at one. The outgoing X incidence is not counted in local rows; outgoing tuple still occupies its actual Y and Z. Keep minimum sum of original tuple weights and an attaining set for each response, infinity only for certified infeasible (a declined solver yields OPEN, not infinity). This can also be viewed as actual smaller native residual: in active mode fix e, remove its Y/Z rows, account for incoming r as externally covered, remove all other outgoing tuples and tuples touching covered rows. Equal residual owner cardinalities s-1. No fabricated choice of incoming tuple in local solve. For no incoming owner all active modes are impossible. Exact local optimization may be capped brute force, signed graphic optimum, or any independently certified exact weighted terminal. Need no enumeration of subsets of incoming arcs. Total number of modes exactly R+W for R regions and W crossing incidences.

Construct bipartite graph with left and right copy of every region. An inactive edge a_L--a_R has weight c_a(0). Each feasible outgoing arc e:a->b supplies edge a_L--b_R of weight c_a(e); parallel edges can retain cheapest actual arc and its witness for optimization with already fixed guards. If a mode has no witness, no edge. Find minimum-weight perfect matching by deterministic exact weighted matching. Each region either matches to itself (inactive) and has no selected incoming or outgoing arc, or sends one selected arc and receives one from another region (active). Inactive edge is distinct from internal source tuple: source internal tuples already inside local response, no crossing self-loop. Thus assignments are precisely vertex-disjoint directed cycle packings including inactive self loops. Forward: every original cover yields such matching and cost at least sum of its mode minima. Reverse: every perfect assignment selects globally consistent actual arc IDs; combine each saved local minimum witness. Each Y,Z owner covered once, each X owner either covered locally or exactly once by its matching incoming tuple. Every original literal guard enforced, every original tuple counted exactly once, no duplicated shared costs. Verify original occupancy and cost. Therefore matching optimum equals original source optimum, and no perfect assignment means source NO when all local responses exact. Works even with unbounded region interaction width, arbitrary many arcs, no log boundary cap and arbitrary signed integer weights. This is a decision/optimization result, not an unweighted exact counting claim (counting assignments with multiplicities is a permanent, no planar property automatically retained).
