## 3. BA06-A: exact dual rejection representation
Define W(z)=span{h_i:s_i(z)=1}. A selector has no lift iff there exists a nonzero linear functional lambda on H such that lambda(a(z))=1 and s_i(z)=0 for every i with lambda(h_i)=1. Both implications are elementary linear separation. Thus the missing-selector set is the union of at most 2^r-1 explicit affine events. For r=1 there is one event, and exact projected cardinality needs only two Gaussian counts. In larger rank do not add event cardinalities independently; overlapping rejection events need exact cancellation. ## 4. BA06-B: subspace-lattice exact projected count

 C_W(U)=#{z : G(z), a(z) in W, s_i(z)=0 for every h_i outside U}.
Each is one explicit affine system; count is zero or 2^(d-rank), computed by Gaussian elimination. The last conjunct is equivalent to W(z)<=U. Let E_W(U) count the same selectors with W(z)=U exactly. Then C_W(U)=sum_{V<=U} E_W(V). Evaluate E_W(U)=C_W(U)-sum_{V<U}E_W(V) in dimension order. All exact E_W(U) are nonnegative. The answer is sum_{W<=H} E_W(W), since each feasible selector belongs to precisely its enabled span class, and the target membership was tested in that same W. This proves exactness for all charts, including arbitrary affine guards. No assignment enumeration in this backend. ## 5. BA06-C: rank-one complete-row counting is #P-complete
Even with one common repair direction and explicit three-row factors, projected count is not full tuple count. For a chart with k(z) enabled directions all equal h, and target h, there are 0 lifts for k=0 and 2^(k-1) for k>0. Construct from any proper 3CNF with n occurring variables and m>=1 clauses: for each clause use all seven nonzero GF(2) linear combinations of its three literal truth values as selectors. For a false clause all seven are zero; for a true clause exactly four equal one (nonzero vector defines a nonzero functional on GF(2)^3). Duplicate each selector K=n+1 times. Hence k(x)=4K times the number of satisfied clauses.

Actual explicit XOR row compiler: one independent base coordinate u_i per selector copy, plus shared repair h. Triple {0,u_i,u_i+h} per copy. For each occurring x_v, an affine binary factor {0, XOR of all u_i whose selector contains x_v}. Use target h plus XOR of u_i with affine constant 1. Base equations force exactly s_i(x), while x_v factors retain distinct original choices. The coefficient dictionary and factors have polynomial total encoding size, and H=<h> meets every triple plane in exactly one dimension. This chart is exact both ways. For proper distinct-variable clauses every local triple row is globally supported when m>=1: for s=1 use a duplicate for any required odd repair; for s=0 choose a nonzero literal truth vector in the kernel of that nonzero functional and use another selector; variable factors likewise admit both values by satisfying some clause. Thus necessary row closure cannot delete any row on this family. No physical E4/B4 adapter claimed for this reduction.

If Z is complete row tuple count at target h, then 2Z=sum_{x:k(x)>0} 2^{k(x)}. Put B=2^(4K). Every coefficient of this base-B sum is at most 2^n < B, so
 #SAT(F)=floor(2Z / B^m).
No carries, one counting query and polynomial-bit arithmetic. Membership in #P follows from explicit row-choice verification. This proves #P-completeness under polynomial metric reductions already at repair rank one, even though positive feasibility is trivial for the constructed formulas (any assignment satisfying one clause suffices). A uniform polynomial full-tuple counting terminal at fixed repair rank would imply FP=#P and P=NP. It is not an unconditional lower bound or a decision obstruction. BW06 removes physical multiplicity for its own compiler; it cannot remove intrinsic row repair multiplicity in this construction without another theorem. BD06's counting-resurrection barrier is complementary, not needed here.
