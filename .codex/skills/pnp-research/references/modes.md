# Mode playbooks

Choose one primary mode per run. Cross-mode handoffs are encouraged; role drift is not.

## structure

Use for exact SU/vMS/RMV construction work.

Primary responsibilities:
- transcribe exact generator/encoder/projection/extractor definitions from primary sources;
- expose final Boolean coordinate maps (g_i(u));
- track adaptive query addresses;
- determine Boolean ANF degree or another exact multiplication-span identity;
- reject schematic RMV substitutes when a construction-specific definition is required.

Primary handoff:
- exact coordinate formulas and source parameters to `product-span`.

Falsification target:
- a legal realization in which adaptivity or encoding produces high Boolean degree / large product span.

## product-span

Use for the quadratic-rank/sparse-(Q) route.

Primary object:
[
\rho(E_H)=\dim_{\mathbb F_2}\operatorname{span}\{1,g_i,g_i g_j\}.
]

Responsibilities:
- apply affine/source-degree lemmas only when hypotheses are exact;
- compute exact finite ranks for the real construction;
- search for independent minors;
- derive sparse annihilator consequences with all description/evaluation costs;
- retire the route if an (Omega(m^2)) construction-compatible minor appears.

Primary handoff:
- rank/annihilator statement to `reconstruction`.

## reconstruction

Use for Viola/vMS reconstruction, quantifier, and exponent accounting.

Responsibilities:
- write exact SAT-query predicates;
- expose YES witnesses and NO universal conditions;
- track dependence on Arthur randomness, indices, and shared (Q);
- model-match RAM-to-SAT/Cook-Levin lengths;
- charge acquisition, normalization, census/output, amplification, indexing, and writing;
- keep the conservative (k^4) ledger unless a full quantitative improvement is proved.

Primary handoff:
- exact exponent/quantifier ledger to `synthesis`;
- escape cases to `red-team`.

## red-team

Use to falsify current proof arrows.

Attack:
- exact encoder rank premises;
- common-(Q) acquisition;
- quantifier flattening;
- source/provenance BIND claims;
- TC4/foreign-algorithm escape abstractions;
- primitive-trace potentials;
- model-transfer claims.

Always distinguish:
- failure of a (P\neq NP) route;
- positive evidence for (P=NP).

The former is not automatically the latter.

For every falsification, state the weakest plausible repair.

## synthesis

Use only when reconciling the project state.

Responsibilities:
- read all newest verified specialist reports;
- keep only the shortest surviving proof chain;
- remove stale/retired routes from the executive chain;
- preserve open arrows visibly;
- reconcile parameter/exponent ledgers;
- set one single team target;
- update root `main.tex` conservatively.

Do not “average” conflicting claims. Resolve them from exact hypotheses/evidence or mark the conflict OPEN.

## experiment

Use for Codex implementation/testing.

Responsibilities:
- convert one precise mathematical question into executable code;
- prefer exact arithmetic and exhaustive search when feasible;
- make randomness seeded;
- store raw results;
- add unit tests for hand-checkable cases;
- run hostile controls;
- minimize counterexamples;
- label finite conclusions COMPUTATIONAL.

Never invent missing theorem definitions to unblock implementation. Missing source definitions are themselves a useful result and should be reported.
